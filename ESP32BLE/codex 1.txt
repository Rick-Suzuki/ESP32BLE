Current PDF renderer and hierarchy

Confirmed:

• PDFKit is already in use: import PDFKit at Set_ImgPanel.swift line 3.
• The preview is a SwiftUI SettingsPDFPreviewPanel containing a UIKit PDFView through UIViewRepresentable.
• The panel is black, has a 2-point white border, and forces a 1.3 width-to-height preview ratio.
• The table supplies this panel below the PDF list.
• PDFView uses:
   • autoScales = true
   • .singlePage
   • vertical direction
   • no page breaks
   • no page-view controller
   • isUserInteractionEnabled = false
• updateUIView resets the PDF scale to scaleFactorForSizeToFit.

Therefore the existing preview is first-page-oriented and display-only. PDFKit can represent multi-page documents, but current settings do not expose page movement because the view is single-page and interaction is disabled.

PDF selection, restoration, file operations

Confirmed:

• A PDF table tap calls selectPDF, persists its path and filename in AppStorage, and copies its filename to the pasteboard.
• Re-selecting the same PDF still invokes selection; there is no current local editor-presentation state.
• The selected PDF is restored by resolving the persisted path first, then filename case-insensitively.
• A missing persisted PDF selection is cleared during document-directory reconciliation.
• The table restores visibility of the selected PDF row using ScrollViewReader.
• Rename moves the file, refreshes documents, and persists the target URL.
• Deleting the selected PDF clears its persisted selection.
• PDF import is supported through all-files import; after import, the first imported PDF becomes selected when PDFs were the import category or no PDF was previously selected.
• There is no existing PDF-specific “preview restoration” state like Images, and no existing iPhone PDF Close behavior.

Multi-page recommendation

Recommended Stage 4D behavior:

• Keep the four existing controls for PDF-file navigation only.
• Use native PDFKit interaction for pages within the selected file.
• Configure PDFView for continuous vertical pages so users can move through a multi-page PDF with native scrolling when at minimum scale.
• Use PDFKit’s own magnification and pan handling rather than layering SwiftUI MagnifyGesture and DragGesture over PDFView.
• When a new PDF is selected, assign the new document, move to its first page, and restore the fit scale.
• A renamed PDF should reload from its new URL without altering the selected-file semantics.
• Deleting or clearing a PDF should set pdfView.document = nil.

This avoids competing SwiftUI and UIKit gestures and lets PDFKit manage page metrics, mixed page sizes, bounds, rendering, and pan limits.

Zoom and pan recommendation

For Stage 4D:

• Keep the editor viewport fixed.
• Use PDFKit’s native pinch and pan.
• After the document and view size are established:
   • Fit scale = pdfView.scaleFactorForSizeToFit
   • Minimum scale = fit scale
   • Maximum scale = fit scale × 5.0
   • Initial scale = fit scale
• Disable autoScales once the explicit limits are set so later SwiftUI updates do not reset a user zoom.
• Do not apply the Image zoom/pan implementation to PDF content.
• Do not rasterize pages into images.

This gives the requested equivalent of 1x through 5x while preserving a PDF page’s native rendering quality.
