B. CURRENT COPY BEHAVIOUR

Copy is invoked by the Edit-mode popup’s Copy action:

• MainScreen.copyMainGridActionMenuSelection() calls copySlotForPopupIfPossible().
• The source resolves to its anchor, even if a continuation cell originated the action.
• encodedGridEditClipboardText() serializes JSON, Base64 encoded, into mainGridEditClipboardText.

Clipboard payload V2 contains:

• version
• rawLine: the anchor’s entire stored screen-file line
• span: legacy shape code
• width
• height

The serialized text begins with:
ESP32BLE_GRID_CLIPBOARD_V2:

Copy does not store separate button-property fields. The rawLine is the complete copyable button payload.

Actual raw-line content includes:

• Action/command text, including MIDI command text and widget commands when encoded in the left side.
• Display text, SF Symbol name, emoji, and color where encoded in the right side.
• Hidden state via @@hidden.
• Other Smart Editor content preserved in the raw string.

FunctionKeyEntry parses that raw line into:

• rawLine
• sendTexts
• alternateDisplayText
• buttonColorCode
• isBlankPlaceholder
• isHiddenInNormalMode

Per-button font size and background image are not represented as separate clipboard fields in this implementation. The visible box font is document-level state; background-image selection is likewise not copied as a button property. The raw line is preserved verbatim, so any supported embedded appearance/action metadata remains intact.

C. CURRENT PASTE FLOW

1. The shared Edit popup calls pasteMainGridActionMenuSelection() at Main_Screen.swift:2305.
2. It validates Edit mode and the selected popup target.
3. It snapshots all current slot lines.
4. It calls updatedSlotLinesForPopupPaste() at Main_DocumentActions.swift:487.
5. The helper:
   • Decodes and validates the clipboard.
   • Resolves the target anchor.
   • Determines the copied shape from width/height.
   • Checks grid bounds.
   • Builds the copied button footprint.
   • Checks whether every footprint cell is permitted.
   • Writes rawLine at the anchor and continuation tokens in remaining footprint cells.
6. MainScreen restores the returned lines through restoreFunctionKeySlotLines().
7. ContentView.persistSlotLines() writes the selected screen document atomically, applies refreshed parsed entries, and protects against externally changed/deleted files.
8. MainScreen refreshes the popup frame, records an undo snapshot, and displays “Button pasted.”

Important: normal Paste can replace the selected destination button. It explicitly clears the selected destination footprint before writing the copied footprint at Main_DocumentActions.swift:549-557. That is existing behavior and should remain unchanged.

D. SPAN REPRESENTATION

A spanning button has:

• Anchor cell: the complete rawLine.
• Same-row continuation cells: @@wide.
• Any lower-row continuation cells: @@block, including cells below the anchor’s column.

Supported shapes are:

• 1x1
• 2x1
• 3x1
• 1x2
• 2x2
• 3x2
• 1x3
• 3x3

Shape detection checks the largest supported shapes first and requires the expected continuation tokens.

A 1x1 Paste Small must:

• Preserve the copied payload rawLine unchanged.
• Use a proposed shape of width 1, height 1.
• Write rawLine only at the destination index.
• Write no continuation assignments.
• Never modify clipboard payload width, height, or span.
• Require the destination’s currently stored line to be blank/empty, not @@wide or @@block.

No stale continuation token is possible if Paste Small uses the existing continuationAssignments() helper with a 1x1 shape: that helper returns no assignments. The target must still be validated as one free cell immediately before persistence.

E. REJECTION REASONS

Current paste exposes only these public outcomes:

• success
• nothingToPaste
• notEnoughSpace
• spaceOccupied

However, spaceOccupied is currently not returned by updatedSlotLinesForPopupPaste(). Its collision failures return notEnoughSpace. Therefore, the current UI displays “not enough space” for multiple distinct causes.

Current causes folded into notEnoughSpace:

• Copied shape exceeds row/column grid boundaries: lines 504-507.
• Target index is invalid/outside visible data: lines 497-502.
• Target resolves to a continuation entry: lines 517-519.
• Required footprint exceeds visible slot count: lines 525-528.
• A footprint index is invalid: lines 532-537.
• A non-destination footprint cell contains a button or continuation: lines 543-546.

NothingToPaste covers empty or malformed clipboard payloads.

Edit-mode-off is rejected before paste is called, at Main_Screen.swift:2305-2310.

Paste Small should be eligible only when all of these are true:

• Clipboard decodes and validates.
• Edit mode remains enabled.
• The exact selected destination is still a direct, single free cell.
• The destination is not a continuation cell and does not resolve to an existing button anchor.
• Normal Paste failed because the copied multi-cell footprint is out of bounds or intersects cells outside that one free destination cell.

Paste Small should not be offered for:

• Empty or malformed clipboard.
• Edit mode ended.
• Invalid target.
• Occupied destination.
• Continuation-cell destination.
• Persistence failure/conflict.
• A copied 1x1 button, because normal Paste already fits wherever a valid free cell exists.

G. DATA PRESERVATION

The safe transformation is shape-only, applied to a copied value:

• Use the captured payload.rawLine unchanged.
• Override only the proposed placement shape to 1x1.
• Do not reserialize or mutate mainGridEditClipboardText.
• Do not touch the source button or source continuation cells.

This preserves commands, MIDI text, widget commands, display text, symbols/emoji, color data, hidden state, and any other raw-line metadata.

H. STALE OPERATION SAFETY

A pending confirmation must not trust current selection or current clipboard when the user presses Paste Small.

Minimum reliable commit checks:

• isGridEditModeEnabled is still true.
• selectedDocumentName equals the pending document name.
• Current grid dimensions equal the pending dimensions.
• The pending index remains in functionKeys and visibleBoxCount.
• The pending index itself is still blank/empty.
• It is not @@wide or @@block.
• The captured clipboard payload is still valid.
• Generate the new slot lines from a freshly read current snapshot.
• Persist only through restoreFunctionKeySlotLines().

Capturing the payload snapshot is essential: if the clipboard changes while the confirmation is on screen, Paste Small must use the snapshot the user was asked to confirm, or cancel. Capturing the document name and grid dimensions prevents a screen switch from redirecting the operation.

A full screen-version token is not presently exposed. The fresh destination-cell validation plus ContentView’s existing disk-conflict detection is sufficient for this single-view synchronous operation.

I. SHARED DEVICE COVERAGE

iPhone and iPad share the same implementation:

• One MainScreen.
• One MainGridEditActionMenu.
• One copy/paste handler and placement helper.
• Device-specific code is limited to popup geometry/positioning.

Paste Small therefore needs no device-specific business logic. A standard SwiftUI confirmation alert will receive native iPhone/iPad presentation.

J. REGRESSION RISKS

Highest risks:

• Accidentally changing normal Paste replacement semantics.
• Allowing Paste Small on an occupied/continuation target.
• Leaving stale @@wide or @@block tokens by manually editing slot lines.
• Mutating the clipboard rather than using a shape override.
• Creating a second undo entry or missing the undo snapshot.
• Saving after a document switch or clipboard change.
• Bypassing persistSlotLines(), which would skip immediate refresh and external-file conflict protection.
• Reusing Move/Cut helpers; this would broaden behavior unnecessarily.

Move, Cut, import/export, MIDI parsing, image-backed appearance, and widget behavior need not change if the implementation stays in the popup Paste path and preserves rawLine.
