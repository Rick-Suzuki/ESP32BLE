Files modified:
ESP32BLE/Scrns/Set_Screen/Set_Screen.swift

New Sound image persistence:
• Replaced Sound-specific path/name storage with:
settingsSoundBackgroundImageIndex
• It is an independent @AppStorage Int with default value 0.
• Sound opacity remains independently stored in settingsSoundBackgroundOpacity.

Obsolete Sound path/name code removed:
• Removed settingsSoundBackgroundImagePath.
• Removed settingsSoundBackgroundImageName.
• Removed path/name URL resolution and URL-based Sound selection persistence.
• Existing Main Screen selectedBackgroundImagePath, selectedBackgroundImageName, and selectedBackgroundImageIndex were not modified.

Index clamping:
• selectedSoundBackgroundImageURL resolves the existing sorted availableImageURLs list.
• Empty list returns nil, so the Sound player uses its existing black fallback.
• Nonempty lists clamp the stored index to 0...(count - 1).
• The index is normalized on Settings appearance and document-directory snapshot changes.
• Empty lists normalize the saved Sound index to 0.

Navigation:
• Back selects index 0.
• Previous selects index - 1 and stops at zero.
• Next selects index + 1 and stops at the final index.
• Random uses one local image-list snapshot and index mapping to choose a different image whenever multiple images exist.
• Each action uses the shared Sound index-selection helper and does not repeatedly enumerate the image directory during that action.
• Existing feedback and press-and-hold behavior remain unchanged.

Image-loader integration:
• The player continues to receive the URL resolved from the clamped Sound index.
• The existing ImageIO worker, one-active-decode policy, latest pending request, intermediate presentation, target-size checks, and final-image safeguards were not changed.

Opacity:
• Selecting an image only changes the Sound index.
• Sound opacity remains independent and persists unchanged.
• At zero opacity, the selected index remains saved while the player appears black.

Validation:
• Xcode diagnostics: no issues in Set_Screen.swift or Set_SoundPlayer.swift.
• ESP32BLE active-scheme build: successful.
• No install, launch, commit, or push performed.

Remaining risks:
• Adding, renaming, or deleting images can intentionally change which sorted-list image occupies the saved index.
• Legacy Sound path/name UserDefaults values are no longer read; the new index starts at zero for existing installs.
• Physical-device testing is still required before confirming behavior on iPad Air M2.
