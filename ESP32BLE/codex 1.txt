1. Supported hardware and USB connections

Confirmed: the app expects an ESP32 BLE peripheral exposing UART-style service UUID 6E400001… with RX/TX/device-ID characteristics (ESP32BLE/Scrns/BLE/BLE_KB_Manager.swift􀰓).

A matching firmware candidate exists outside the active project: ../moved out/Arduino/ESP_32_2v3.ino. It identifies itself at runtime as an “ESP32-S3 … keyboard bridge” (:649) and uses native USB HID keyboard APIs (:1-3, 53-55, 644-645). No specific commercial ESP32-S3 board, USB-UART wiring, USB-OTG wiring, boot-button procedure, or tested alternative board is documented. Its GPIO status outputs indicate custom hardware (:20-40), so other boards are unverified.

2. Firmware installation findings

No firmware project, binary, upload script, installer, or installation guide is bundled in the active ESP project. The candidate .ino uses Arduino/ESP32 headers, but its required board package, drivers, upload port, and configuration are undocumented. No precompiled firmware was found. Firmware update steps therefore require confirmation before public instructions.

3. First-start behavior

Candidate firmware initializes USB HID, starts BLE advertising, and restarts advertising after a client disconnects (ESP_32_2v3.ino:577-610, 644-675). It defines LED patterns: brief pulse while unconnected, mostly-on when connected, fast blink after activity (:223-273). This is not confirmed as the current shipping firmware. No reset/button requirement is documented.

4. BLE discovery and connection

ESP—not iOS Settings—controls connection. Selecting ESP32 output mode starts scanning (ContentView.swift􀰓) for the service UUID (BLE_KB_Manager.swift􀰓). The Settings device list shows discovered peripheral names; tapping one selects and connects (Set_AvailableDevices.swift􀰓). The displayed name is firmware-defined; the candidate advertises “PS5 Keyboard Bridge A” (ESP_32_2v3.ino:13), while the app does not enforce a name (BLE_KB_Manager.swift􀰓). Status shows “ESP32: Connected” or “Searching…” (Set_AvailableDevices.swift􀰓). Disconnection/failure resumes scanning (BLE_KB_Manager.swift􀰓). No app pairing flow exists. Bluetooth unauthorized/off states are surfaced (:366-385); no setup guidance is present.

5. Keyboard testing

Connected status enables Set & Test (Set_Screen.swift􀰓). It sends timing, then:
Hello World! ABC abc 123 456 aa BB 11 !! ?? -- ..

Firmware defaults are 20 ms down/70 ms gap (ESP_32_2v3.ino:99-100); no first-install adjustment is documented. Output targets the USB HID host connected to the ESP32-S3, not the iPhone/iPad.

6. Relevant troubleshooting

Confirmed visible states: “No ESP32 devices found yet,” “Select an ESP32 first,” “Selected ESP32 not found,” Bluetooth off/not authorized/not supported, service/characteristic discovery failure, failed connection, and disconnected (Set_AvailableDevices.swift􀰓; BLE_KB_Manager.swift􀰓).
