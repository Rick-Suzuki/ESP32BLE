For C columns, R rows, GeometryReader height H, and iPad reserved bottom inset of zero:

spacing(R) = 10 - 6 × ((C × R) - 1) / 143

cornerRadius(R) = 20 - 15 × ((C × R) - 1) / 143

availableGridHeight(R) = H + 30 - ((R - 1) × spacing(R))

oneRowButtonHeight(R) = availableGridHeight(R) / R

For the two configurations:

7 rows:
• spacing7 = 10 - 6 × ((7C) - 1) / 143
• radius7 = 20 - 15 × ((7C) - 1) / 143
• height7 = (H + 30 - 6 × spacing7) / 7

8 rows:
• spacing8 = 10 - 6 × ((8C) - 1) / 143
• radius8 = 20 - 15 × ((8C) - 1) / 143
• height8 = (H + 30 - 7 × spacing8) / 8

A multi-row button has:

height(span) = oneRowButtonHeight × span + spacing × (span - 1)

Its vertical origin is:

row × (oneRowButtonHeight + spacing)

There is no pixel rounding in these calculations. Both the dimensions and origins may therefore be fractional points; the physical-pixel result also depends on the iPad’s display scale.

The exact numeric H, C, display scale, and tested button span are runtime values, so the source alone cannot truthfully provide final point/pixel measurements for the physical device.

B. EFFECTIVE CORNER RADIUS

All relevant layers receive the same configured source radius:

• Normal gray background: mainGridButtonCornerRadius
• Normal gray border: mainGridButtonCornerRadius
• Active green MIDI Note border: mainGridButtonCornerRadius
• Active green MIDI CC one-shot border: mainGridButtonCornerRadius
• Parent clipping shape: mainGridButtonCornerRadius

The configured radius decreases only slightly when moving from seven to eight rows because it is based on total button count, not actual button height. The cell height decreases much more substantially.

Therefore the corner-radius-to-height ratio rises at eight rows.

SwiftUI’s documented strokeBorder behavior is an inner stroke: it insets the shape by half its line width before applying the stroke. Thus:

• Gray border: 2 pt strokeBorder, centerline inset by 1 pt.
• Green border: 3 pt strokeBorder, centerline inset by 1.5 pt.

The green border’s effective drawing region is therefore smaller than the gray border’s. This becomes more significant as button height decreases.

The public API documentation does not specify the internal clamping/path-normalization behavior of RoundedRectangle when a requested continuous corner radius is large relative to a shallow, fractional frame. That final rendering behavior needs device measurement to confirm.

C. FULL BORDER AND CLIPPING HIERARCHY

For a MIDI Note button:

1. MainScreenGridSection calculates a fractional cell frame.
2. gridButtonView creates MIDINoteButton with that frame and the shared corner radius.
3. MIDINoteButton’s label is MainScreenButtonLabelView.
4. MainScreenButtonLabelView draws:
   • RoundedRectangle background
   • Optional image
   • 2 pt normal gray strokeBorder
   • Button content
5. MIDINoteButton draws the 3 pt green strokeBorder after the label when activeToken is non-nil.
6. MIDITouchView is placed last, but is a transparent UIKit touch-capture view.
7. MainScreenGridSection applies the fixed frame.
8. MainGridButtonBoundsClip clips the entire result with RoundedRectangle using the same configured corner radius.
9. The optional selected-action white border is applied after clipping, but only for an action-menu-selected cell.

For a MIDI CC one-shot button:

1. The same label and normal gray shell are used.
2. MainGridMIDIMomentaryButtonStyle overlays the 3 pt green strokeBorder only while configuration.isPressed.
3. The same outer grid-cell frame and parent clip are applied.

The green active border is above the gray normal border. There is no subsequent gray border layer that can cover the green top and bottom edges. If gray remains visible there, the active path is not painting those pixels or is being removed by shape/rasterization/clipping behavior; it is not simply behind the gray border.

D. MOST LIKELY ROOT CAUSE

The source has no state, row-count conditional, MIDI event path, or overlay-order branch that changes specifically at seven versus eight rows.

The source-supported cause is height-sensitive rendering geometry:

• Eight rows produces a materially shorter cell frame.
• The configured radius does not scale from actual cell height.
• The active green border is a 3 pt inner stroke, leaving less effective vertical drawing space than the 2 pt gray border.
• The grid uses fractional point heights and positions without display-scale alignment.
• The entire result is clipped by a separate outer RoundedRectangle.

This makes the active 3 pt continuous rounded border the most likely geometry-sensitive layer. The seven/eight threshold is consistent with SwiftUI/Core Graphics path normalization or rasterization once the shorter frame reaches a particular radius-to-height and fractional-pixel combination.

There is no evidence that MIDI Note-On, Note-Off, toggle tokens, or touch handling cause the missing top/bottom edges. Both active-border paths use the same full RoundedRectangle strokeBorder.

E. STAGE 8B.31A ASSESSMENT

Recommendation: revert the Stage 8B.31A normal-border change in a future, explicitly authorized implementation stage.

Reason:
• Physical testing found no meaningful improvement.
• The actual issue is in the active green border’s short-cell rendering path, not the normal gray border’s placement.
• Stage 8B.31A changed the normal border geometry for all populated iPad buttons, including ordinary buttons.
• Although the change is internally reasonable, it is unrelated to the demonstrated failure and adds an unnecessary visual difference to the baseline.

Nothing was reverted during this read-only stage.

F. RECOMMENDED MINIMAL CORRECTION

First perform one narrow device diagnostic before changing rendering.

If that confirms the expected radius-to-height threshold, make one shared active-green-border helper used by both:

• MIDINoteButton
• MainGridMIDIMomentaryButtonStyle

The helper should derive its active rounded-rectangle radius from the actual rendered size and clamp it only when needed for shallow cells. The normal gray border, parent clipping, button frame, spacing, touch target, and MIDI state logic should remain unchanged.

The helper should preserve the configured corner radius for normal and tall buttons. Only a short cell whose available height cannot safely accommodate the active 3 pt inset stroke should receive a reduced active-border radius.

This is narrower and safer than changing grid dimensions, changing normal borders, changing clipping, or adding model-specific rules.
