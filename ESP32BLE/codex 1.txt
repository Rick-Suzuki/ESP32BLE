Implemented Stage 6C.5.

Files modified:
• ESP32BLE/Scrns/Set_Screen/Set_Screen.swift
• ESP32BLE/Scrns/Set_Screen/Table_Img/Set_Table.swift

Cause addressed:
• Rapid Screen/Text/MD navigation created successive UUID-based scroll requests.
• Each could start a 0.35-second table-scroll animation, while SwiftUI still had intermediate editor updates pending.

Latest-request identity:
• Reuses the existing SettingsDocumentNavigationScrollRequest.id.
• The request UUID is now logged when created.
• The document table captures that exact request, yields once, then verifies it is still current before scrolling.

Obsolete scroll prevention:
• A cancelled or stale task logs 🐞 and does not scroll.
• The handler verifies the current bound request ID both before validation and immediately before scrolling.
• A stale task cannot clear or consume a newer request.
• Processed request IDs are tracked locally by the table, so an already-handled request is not replayed.

Animations:
• Document navigation scrolling is now immediate rather than using the prior 0.35-second animation.
• This prevents document navigation animations from stacking during rapid presses.
• Image and PDF navigation animations are unchanged.

Editor changes:
• No PlainDocumentEditor or editor-state changes were necessary.
• File transitions remain synchronous and preserve save-before-switch, conflict detection, atomic writes, selected text, saved baseline, loaded URL/name, and Screen yellow/green separation.

Shared behavior:
• The coalesced document-scroll path applies equally to Screens, Text, and MDs.
• Images and PDFs are untouched.

Diagnostics:
• Existing Stage 6C.3 timing diagnostics remain.
• Added concise 🐞 messages for created, superseded, ignored, and accepted document scroll requests.

Build result:
• ESP32BLE built successfully for the active physical-device destination in 21.8 seconds.

Remaining limitation:
• This safely removes stale table-scroll work, but it does not independently cancel already-queued SwiftUI text-render passes. Physical testing should confirm whether eliminating stacked document scroll animations gives the expected prompt latest-selection presentation.
