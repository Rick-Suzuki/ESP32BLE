1. New editing-session state

Added private Templates-only TemplateEditingSession state in Set_Screen.swift􀰓.

It keeps separate from the existing Screens/Text/Markdown editor:

• Original template URL.
• Original template and configuration file data snapshots.
• Original template contents and description.
• Independent template-contents and description drafts.
• Saved status and session validity.
• Separate template load/save error state.

It does not use documentEditorText, loadedDocumentURL, or saveCurrentDocumentText().

2. Session loading

Added prepareTemplateEditingSession(for:).

It:

• Confirms the URL belongs to the current Templates collection.
• Confirms the template exists.
• Reads UTF-8 template contents.
• Reads and validates the companion configuration.
• Preserves ScreenConfig.
• Initializes independent drafts only after complete successful loading.
• Presents the existing Settings alert on failure.
• Does not create a partial or empty fallback session.

3. Paired-file update

Added updateTemplateDocument(...) in TemplateDocument.swift􀰓.

It preserves the existing two-file format:

• Name.template
• Name.template.config.json

The helper:

• Verifies both files are regular files.
• Verifies original file snapshots match the editing session.
• Validates original template UTF-8 and configuration JSON.
• Preserves the existing ScreenConfig.
• Normalizes whitespace-only descriptions to nil.
• Preserves nonempty description text, including Unicode and line breaks.
• Encodes and decodes replacement JSON before publication.
• Creates staged replacement files in the template directory.
• Verifies staged UTF-8 and JSON data.
• Creates and verifies recoverable on-disk backups before publishing either replacement.
• Publishes config and template replacements as a coordinated pair.
• Verifies both final files after publication.
• Removes temporary staging/backups only after the operation completes.

4. Validation and rollback

Before publication, the helper validates:

• Template identity and existence.
• Companion config existence.
• UTF-8 template encoding.
• Existing JSON configuration.
• Button count against maxFunctionKeyCount.
• Existing grid capacity against the edited template.
• Replacement JSON encoding/decoding.
• Staged file contents.

If either publication step fails, it restores both files from verified backups. A rollback failure is surfaced explicitly as a critical error.

5. Stale-session safeguards

saveTemplateEditingSession() rejects saving when:

• No valid editing session exists.
• The selected template changed.
• The edited template is no longer in the Templates collection.
• Template contents changed externally since loading.
• Companion configuration changed externally since loading.

The drafts remain in memory after a failed load/save attempt for correction or retry; there is no automatic redirect to another selected template.

6. Post-save refresh

After both files are saved and reloaded successfully:

• The session snapshots are replaced with the verified saved files.
• The session is marked saved.
• The selected path remains the edited template.
• refreshTemplateFiles() reloads the Templates collection and description state.

No editor presentation or dismissal is triggered; that remains for Stage 8B.24B.

7. Error handling

Failures use the existing presentDocumentSaveAlert style. The new update error type covers missing files, invalid UTF-8/JSON, stale source data, invalid template/grid content, staging, backup, publication, and rollback failure.

8. Diagnostics added

Added timestamped 🐞 diagnostics for:

• Editing-session initialization.
• Session loading failure.
• Save begin.
• Selection/unavailable save rejection.
• Save failure/success.
• Rollback attempt, success, and failure.

No template or description contents are logged.
