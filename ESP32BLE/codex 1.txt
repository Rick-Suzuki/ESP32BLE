Current size behavior

Both iPhone and iPad use the same SwiftUI semantic font declarations:

• Section title: Title 2, approximately 22 points at the default Dynamic Type size.
• Menu row label: Body, approximately 17 points at the default Dynamic Type size.
• Chevron: Caption, approximately 12 points at the default Dynamic Type size.

There is no Help-menu device-specific font conditional, fixed font size, Dynamic Type environment override, minimum-scale factor, or custom scaling modifier.

Explanation

The source does not intentionally make iPhone menu text larger. iPhone and iPad receive the same semantic font styles. The perceived difference is therefore caused by physical display size, available landscape space, device display scaling, or different user Dynamic Type settings—not an iPhone-specific Help font rule.

Layout findings

Both menus use the same layout:

• Title-to-scroll spacing: 20 points.
• Row vertical padding: 14 points.
• Row icon frame width: 24 points.
• Outer padding: default 16 points.

No iPhone-specific row height, icon size, or menu spacing exists. The same ESPHelpContentsRow is used by both the six-item root Contents menu and the five-item Using ESP submenu.

Recommended minimal implementation

Use semantic styles, preserving Dynamic Type:

• iPad: retain Title 2 for headings and Body for rows.
• iPhone: use Title 3 for headings and Subheadline for rows.

This reduces headings from approximately 22 to 20 points and row labels from approximately 17 to 15 points, while continuing to respond to the user’s Dynamic Type setting.

Apply the row font at the shared ESPHelpContentsRow HStack level so the primary SF Symbol scales consistently with the text. Keep the chevron’s existing Caption font.

No row-spacing or icon-frame adjustment should be necessary initially. Reducing row text modestly lowers natural row height while the existing 14-point vertical padding preserves a comfortable touch target.
