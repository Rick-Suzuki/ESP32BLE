VERIFIED

Current category switch path:
• Category selection calls selectSettingsListMode(), which changes listMode.
• SettingsDocumentTableSection stays structurally unchanged because its only explicit identity is importRefreshID, not listMode.
• One List and one ScrollViewReader contain a switch that swaps ForEach content by category.
• selectionRestorationID changes with category/rows, so the existing task runs.
• The PDF diagnostic proves the target path exists and scrollProxy.scrollTo executes.

The List has no category-specific identity. Switching Sounds to PDFs replaces the ForEach branch while retaining the same List/ScrollViewReader subtree identity.

INFERRED ROOT CAUSE

The restoration task is running during the category transition before the reused native List has registered the replacement PDF rows as active scroll targets. ScrollViewProxy silently has no effective target at that instant.

Settings recreation differs because it constructs a new SettingsScreen/List subtree; by the initial restoration task, the active category’s rows are available. This matches the successful Main → Settings behavior.

The same structural risk applies to all categories. Physical failure is confirmed only for PDFs; Images are likely affected. Sounds work when reopening, not yet proven when switching categories.

RECOMMENDED MINIMAL FIX

Give the existing ScrollViewReader subtree a category-specific identity:

.id(listMode)

Apply it to the ScrollViewReader, not the whole Settings table. This recreates the reader and native List only when the category changes, while preserving:
• Existing List/swipe actions
• Stable row IDs
• Selection state
• Preview layout
• Restoration task and scrollTo behavior

No separate category-transition event is needed: the existing task(id: selectionRestorationID) already provides it.

Do not add delays, retries, or new diagnostics. The existing logs are sufficient to validate the targeted change on device.

COMPATIBILITY

.id(_:) is supported on iPadOS 17.7.11. The primary regression risk is category switching recreating List-local transient state, which is intended here; persistent selection state already lives outside the List.
