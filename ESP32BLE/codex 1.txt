Exact cause

SettingsDocumentTableSection.loadedDocumentURL is not receiving the editor’s actual loadedDocumentURL.

At Set_Screen.swift:1804, the table is constructed with:

loadedDocumentURL: selectedDocumentFileURL

selectedDocumentFileURL is the active .screen URL, not the Settings editor’s @State private var loadedDocumentURL.

Therefore, after selecting notes.txt or notes.md:

• the selection path correctly changes to that file;
• the editor’s real loadedDocumentURL correctly changes to that file;
• but the table still receives the active screen URL;
• the row comparison fails, so no row becomes green.

Affected current conditions:

• Set_Table.swift:568 text row:
selectedTextSelectionPath == textURL.path && loadedDocumentURL == textURL

• Set_Table.swift:616 Markdown row:
selectedMarkdownSelectionPath == markdownURL.path && loadedDocumentURL == markdownURL

The URL comparisons themselves are correct: both use standardizedFileURL.

Actual state flow

1. A text-row tap calls loadTextFile(textURL) at Set_Table.swift:574.

2. loadTextFile sets selectedTextSelectionPath and, after successful UTF-8 loading, sets the real editor loadedDocumentURL at Set_Screen.swift:2328.

3. Markdown follows the same pattern at Set_Screen.swift:2349.

4. SwiftUI correctly observes those @State changes, but the child table receives selectedDocumentFileURL instead of the state value. This is the failure point.

There is no missing binding, stale row identity, or timing issue. The child table has proper bindings for selected paths; the wrong value is supplied for its separate loaded-document input.

Recommended minimal correction

Change only the table-construction argument at Set_Screen.swift line 1804 from:

loadedDocumentURL: selectedDocumentFileURL

to:

loadedDocumentURL: loadedDocumentURL

This preserves the existing two-part green condition:

• selected path identifies the category’s selected row;
• actual editor URL proves that exact document loaded successfully.

It does not weaken save protection. The editor’s save guard remains based on loadedDocumentURL plus loadedDocumentName at Set_Screen.swift:2561.

The existing .files behavior should remain valid: on switching to the screens category, the existing list-mode change flow loads the selected active screen into the editor, making the actual loaded URL again match that screen.
