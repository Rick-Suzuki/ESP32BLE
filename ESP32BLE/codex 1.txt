B. Current selection and scrolling

VERIFIED:
• Each category already has an independent AppStorage scroll ID and stable path-based row identity.
• Screens retain their loaded document selection through the parent ContentView.
• Sounds and PDFs persist selected path/name, but their table highlight is temporary only.
• Text and Templates use Settings-owned @State; both are lost when Settings is removed. Templates are also deliberately cleared whenever another table becomes active.
• Temporary screen/text/sound/PDF highlights are cleared in Set_Table.swift:251-258.
• Images use green for persisted applied image and yellow for temporary preview. The preview is Settings-local.

C. BLACK implementation

VERIFIED:
• BLACK is not an image file. It is a nil image URL / persisted index 0 sentinel.
• The Images table inserts a dedicated BLACK row at Set_Table.swift:120 and 586-648.
• Real images use persisted indices starting at 1; index 0 means no image.
• Screen configurations store a nil background image name for this state; backups do not require a BLACK asset.
• The image preview panel intentionally renders black when its URL is nil: Set_ImgPanel.swift:21-40.

Safe removal: remove only the table’s BLACK row and its navigation entry points, while retaining nil/index-0 compatibility for existing screens. Existing black/no-image screens should remain black, with no green file row selected. Do not renumber real-image persistence.

D. Image controls

VERIFIED:
• Controls are always shown and mostly active, regardless of active table.
• Reset selects nil/BLACK; Random includes nil; Previous can reach nil; Next starts with first real image.
• Controls preview only; they do not apply an image.
• Control actions update image scroll state, but table single-tap preview does not consistently do so.

E. Recommended restoration approach

Use parent-owned, session-lifetime per-table selection IDs, preferably stable file paths, passed into Settings. Retain existing persisted applied image/sound/PDF state. On category activation, validate the stored path against current files, then set that category’s existing scroll-position binding after its rows exist.

For Images, on Settings return set preview equal to the applied image, clearing yellow preview; scroll to the applied green row. If none is applied, retain nil state and scroll to the top without applying an image.

F. Risks

• Removing BLACK must not convert legacy nil backgrounds to a real image.
• Deleted/replaced files require path validation and selection clearing.
• Avoid using array indices; imports, sorting, and deletion make them unstable.
• Scroll restoration should use the existing iOS/iPadOS 17 scrollPosition path IDs, not timing delays.

G. Recommended stages

1. Remove only the BLACK table row; retain nil persistence compatibility.
2. Introduce independent parent-owned selection IDs; stop clearing Templates on category changes.
3. Bind highlights and scroll restoration to those IDs.
4. Gate image controls by Images mode; make Back select the first real image, with no automatic apply.

H. Required decision

When no image is applied, should Images show no highlighted row (recommended), or should it visually select the first real image without applying it?
