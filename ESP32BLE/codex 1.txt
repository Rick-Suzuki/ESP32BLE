Opacity is persisted per screen document:

• ScreenConfig contains backgroundOpacity: ScreenConfig.swift lines 19–39.
• The value is encoded and decoded with the screen config JSON: lines 53–81.
• ContentView saves the changed value into the selected screen config: ContentView.swift lines 1260–1271.

The AppStorage key is global as the live/current value and fallback, but the established saved behavior is per-screen, not per-image.

6. Selection-state implications

The slider does not select or apply an image.

Its existing semantics are:

• It controls the selected screen’s persisted applied-background opacity.
• It is independent of yellow preview selection and green applied-background selection.
• Moving it while a yellow preview differs from the green applied image still changes the selected screen’s background-opacity setting.

Connecting the slider to the large preview would make the preview accurately show the current screen’s background opacity for whichever image is being previewed. It would not require changing image selection, double-tap application, or persistence logic.

7. Editor integration point

Correct future integration point:

• View: SettingsImagePreviewPanel

Apply:

to the rendered Image layer only, after its frame/scale/offset transform and before or after the gesture modifiers.

Do not apply opacity to:

• The clipped ZStack

This preserves zoom, pan, gestures, clipping, border visibility, and fixed viewport geometry. Slider movement would not reset zoom or pan because neither gesture state nor preview identity changes.

8. Black-background result

The preview viewport’s black background is at Set_ImgPanel.swift line 35.

Reducing image opacity over it will progressively blend the image toward black. It will not reveal checkerboard transparency or the underlying Settings UI.

This matches the Main Screen’s actual composition: Main_BG_img.swift places Color.black behind the image before applying background-image opacity.

Recommendation: retain the black editor background. It provides the closest visual representation of the Main Screen background at reduced opacity. A different background would be a separate design decision and would no longer represent the current Main Screen result.

10. Risks and unresolved design decision

Low implementation risk:
• .opacity affects only visual compositing; it does not alter layout, image decoding, pan limits, zoom scale, clipping, or gesture recognition.

Behavioral consideration:
• If a yellow preview image differs from the green applied background image, changing the slider changes the selected screen’s persisted applied-background opacity while simultaneously previewing that opacity on the yellow image. This is consistent with the existing shared slider state, but it should be accepted as the intended UX before implementation.

No iPhone/iPad compatibility issue was found. Both paths share the same 0...1 AppStorage state, and .opacity is supported across the project’s iOS 17.6 deployment target.
