1. Correct BLE connection property

Confirmed: use ble.isConnected. It is @Published in ESP32BLE/Scrns/BLE/BLE_KB_Manager.swift􀰓 and Settings observes ble (Set_Screen.swift􀰓), so controls update on connect/disconnect. It becomes true in didConnect (BLE_KB_Manager.swift􀰓) and false on disconnection (:525-540). It is also used by Settings device UI (Set_AvailableDevices.swift􀰓).

Caveat: it becomes true before service/characteristic discovery finishes; no published “RX ready” state exists.

2. Current timing control enablement

Confirmed: SettingsKeyboardTimingSection independently disables ON/OFF controls with isTimingControlsEnabled (Set_KB_Timing.swift􀰓) and its button with isTestEnabled (:75-100). ESP-TEST-002 successfully separated them. Currently isCustomKeyboardTimingEnabled is only !isMacKeyboardTestMode (Set_Screen.swift􀰓), so ESP32 controls remain enabled while disconnected. REC OFF is outside that disabled group (Set_KB_Timing.swift􀰓).

3. Existing Set & Test action guards

Mac mode rechecks macConnection.canSend before sending (Set_Screen.swift􀰓). ESP32 mode has no immediate ble.isConnected guard (:1933-1934). However, sendLine rejects sends without both peripheral and RX characteristic (BLE_KB_Manager.swift􀰓).

4. Smallest recommended correction

Change isCustomKeyboardTimingEnabled to:

!isMacKeyboardTestMode && ble.isConnected

This automatically disables ESP32 ON/OFF and Set & Test, while preserving Mac Test’s macConnection.canSend behavior. Add guard ble.isConnected else { return } immediately before the ESP32 timing-command/test-string sends. Keep their existing order unchanged.
