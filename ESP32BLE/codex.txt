3. New safe replacement helper

Added safelyReplaceExistingImportedFile(from:to:).

It:

• Creates an item replacement directory.
• Stages the incoming file first.
• Verifies the staged file exists and matches source file size when available.
• Calls FileManager.replaceItemAt.
• Cleans up the staging directory with defer.
• Does not remove the original file before staging succeeds.

4. Staging directory implementation

Uses:

FileManager.default.url(for: .itemReplacementDirectory, in: .userDomainMask, appropriateFor: targetURL, create: true)

The staged file is placed inside that replacement directory using a UUID filename plus the target extension.

Staging files are not placed directly in Documents, so they should not appear in the normal Settings file list.

5. FileManager replacement implementation

Uses:

FileManager.default.replaceItemAt(targetURL, withItemAt: stagedURL, backupItemName: nil, options: [.usingNewMetadataOnly])

If replacement fails:

• The code does not delete targetURL.
• It does not retry with remove/move.
• It checks whether the destination still exists.
• It logs any Foundation recovery original location from NSFileOriginalItemLocationKey using db().
• It throws through the existing restore error path.

6. Screen/configuration handling

For .config.json restore replacements:

• safelyReplaceExistingScreenConfig reads and decodes the source config before replacement.
• Invalid config data is not written over an existing config.
• Existing configs are replaced with the same safe replacement helper.
• New configs still use the existing new-file import path.
• If a replacement screen has no matching backup config, an existing valid config is preserved.

Skip All still preserves skipped screens and matching configs.

7. Error handling and recovery behavior

Existing restore failure handling is preserved:

• Failures are recorded with recordImportFailure.
• renameAlertMessage reports the failed file.
• The restore session continues according to the existing flow.
• Temporary staging resources are cleaned up with defer.

This is still per-file safety, not a transactional restore.
