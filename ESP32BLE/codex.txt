MIDI-010B-4 IMPLEMENTATION REPORT

1. Exact file modified

Production ESPMacHelper:

ESPMacHelper/MacNetworkServer.swift

MIDIOutputService.swift did not require modification.

The existing Xcode UserInterfaceState.xcuserstate modification was already present and was not changed intentionally.

ESP32BLE and the experimental Test Area Helper were not modified during this phase.


2. ParsedMIDICommand changes

Note On now retains:

note: UInt8
velocity: UInt8
networkChannel: UInt8

Note Off now retains:

note: UInt8
networkChannel: UInt8

The networkChannel name identifies it as the user-facing, one-based value received from ESP32BLE.


3. Channel validation

Both Note On and Note Off accept channels 1 through 16.

The parser rejects:

Channel 0.
Channel 17 or higher.
Negative channels.
Non-numeric channels.
Missing channel fields.
Extra fields.
Malformed MIDI commands.

No invalid channel is silently replaced with channel 1.

Existing validation remains:

Note: 0...127.
Velocity: 1...127.


4. Channel conversion

Conversion occurs once in MacNetworkServer.handleCommand, immediately before dispatch to MIDIOutputService.

Conversion:

coreMIDIChannel = networkChannel - 1

Therefore:

Network 1 becomes CoreMIDI 0.
Network 2 becomes CoreMIDI 1.
Network 16 becomes CoreMIDI 15.

MIDIOutputService continues to receive and store only zero-based CoreMIDI channels.


5. Note On handling

Example input:

MIDI:NOTE_ON:60:127:2

Parsed values:

Note 60.
Velocity 127.
Network channel 2.

Dispatched to MIDIOutputService as CoreMIDI channel 1.

The existing immediate CoreMIDI submission path remains unchanged.


6. Note Off handling

Example input:

MIDI:NOTE_OFF:60:2

Parsed values:

Note 60.
Network channel 2.

Dispatched to MIDIOutputService as CoreMIDI channel 1.

Note Off uses the channel supplied by the network command and does not affect note 60 on another channel.


7. Note and channel ownership

MIDIOutputService already keys active notes using:

NoteKey(note: UInt8, channel: UInt8)

Consequently, these are independent identities:

Note 60, channel 1.
Note 60, channel 2.

Stopping note 60 on channel 1 does not stop note 60 on channel 2.

Different notes on the same channel also remain independent.


8. Multiple-client behavior

Ownership remains a set of network client identifiers for each note/channel key.

When multiple clients own the same note and channel:

The first owner sends the CoreMIDI Note On.
Additional owners are recorded without duplicating Note On.
CoreMIDI Note Off is sent only when the last owner releases the note.

This behavior was not redesigned.


9. Disconnect cleanup

MacNetworkServer continues to call releaseNetworkNotes(for:) when:

A client connection is removed.
The network server stops.

releaseNetworkNotes examines every note/channel identity owned by that client. Notes still owned by another client remain active.

Panic and shutdown cleanup continue to send Note Off using each stored note’s CoreMIDI channel.


10. Build result

Production ESPMacHelper built successfully.

Exit status: 0.

The command-line build used -disable-sandbox so Swift macro plug-ins could execute inside the tool environment. No project setting was changed.

One pre-existing warning remains in MIDIOutputService.swift:

The result of MIDIEventListAdd is non-optional, making its nil comparison always true.

This warning is unrelated to MIDI channel support.


11. Focused checks performed

Source-level validation confirmed:

Channel 2 converts to CoreMIDI channel 1.
Channel 16 converts to CoreMIDI channel 15.
Channels 0 and 17 are rejected.
Malformed and missing channel fields are rejected.
Note and velocity validation remains unchanged.
Note On and Note Off both retain their parsed channel.
Ownership remains keyed by note plus channel.

Non-MIDI command handling was not changed.

No physical-device, Logic Pro, or live multi-client tests were performed.


12. Known limitation

Two buttons from the same client using the identical note and channel share the same network-client ownership entry. Releasing one can therefore release that shared identity.

This existing limitation is outside MIDI-010B-4 and was not changed.
