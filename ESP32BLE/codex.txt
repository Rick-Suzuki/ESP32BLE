B. Parser changes

MIDICommandParser now supports:

• .midi 60 off
• .midi 60 off 4
• Numeric and pitch note syntax use the existing note parser.
• Omitted channel remains the configured default.
• Explicit channels remain limited to 1...16.

Implementation:

• Added explicit MIDINoteCommandKind (on / off) and a defaulted kind initializer parameter, preserving existing parser consumer construction compatibility: MIDICommandParser.swift lines 6-30.
• Recognizes off only in the velocity position: lines 90-110.
• Rejects off with toggle: lines 93-96.
• Existing positive-velocity syntax, default velocity 127, and Note On toggle parsing remain unchanged: lines 76-130.

Statically verified invalid forms are rejected by the parser structure:

• .midi 128 off
• .midi 60 off 0
• .midi 60 off 17
• .midi 60 off toggle
• .midi 60 off 4 toggle
• .midi 60 off 4 extra

C. Runtime Note Off execution changes

• Added an explicit .noteOff(number:) touch message.
• Parsed off commands become that message rather than a velocity-zero Note On: Main_Screen.swift lines 1475-1479.
• On touch-down, explicit Note Off:
   • calls the existing sendMIDINoteOffFromTouch transport helper;
   • sends MIDI:NOTE_OFF:<note>:<channel>;
   • returns no activation token, so it never sends Note On or creates a new owner.

Relevant code: Main_Screen.swift lines 1529-1546.

• The existing Note Off helper now returns the transport success result while continuing to use the same Mac helper path: Main_ButtonBehavior.swift around lines 832-844.

D. Registry reconciliation behavior

Added targeted reconcileExplicitNoteOff:

• Matches only the active note’s connection session, MIDI channel, and note number.
• Removes all matching active ownership tokens.
• Leaves other notes, channels, and connections intact.
• Prevents a later hold release from issuing a second Note Off for the already explicitly stopped note.
• Allows a subsequent Note On to proceed normally because stale ownership no longer suppresses it.

Relevant code: Main_ButtonBehavior.swift lines 65-81 and 147-156.

Existing positive-velocity hold/toggle mechanics were not changed.

Relevant code: Main_Screen.swift lines 6793 onward.
