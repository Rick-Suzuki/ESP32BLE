4. Wait Task registry design

Main_Screen.swift:867 now owns:

activeWaitChainTasks: [UUID: Task<Void, Never>]

Properties of the registry:

• MainActor-owned.
• One unique UUID per wait sequence.
• Contains every active wait-chain Task.
• Supports simultaneous independent sequences.
• Is cleared immediately during Universal Stop.
• Can support Phase C2 later through an emptiness check.
• Does not use a manager, actor, ObservableObject, timer, or global state.

5. Task registration order

startWaitChainCommandTokens(...) is MainActor-isolated.

It:

1. Creates the sequence UUID.
2. Constructs the MainActor Task.
3. Registers the Task in activeWaitChainTasks.
4. Returns to the MainActor scheduler.
5. The Task then begins executing the command chain.

Because the launcher is synchronous and MainActor-isolated, the newly created MainActor Task cannot execute its command body during that same non-suspending actor turn before registration completes.

This ensures a sequence beginning with .sm is registered before it attempts to cancel itself.

8. Cancellation helper

Main_ButtonBehavior.swift:517–524 adds:

cancelAllWaitChainCommands()

It:

1. Copies the currently registered Task handles.
2. Clears activeWaitChainTasks immediately.
3. Cancels every copied Task.

It is safe when:

• No sequence is active.
• One sequence is active.
• Multiple sequences are active.
• Stop is invoked repeatedly.
• A cancelled Task later performs deferred cleanup.

Only wait-chain Tasks in this registry are cancelled.

10. Task.sleep cancellation handling

The previous:

try? await Task.sleep(...)

was replaced with explicit do/catch.

If cancellation interrupts the sleep:

• Task.sleep throws.
• The catch returns from the executor.
• No subsequent token executes.
• Cancellation is not treated as successful wait completion.

Wait duration calculation and invalid-wait handling were not changed.

11. Cancellation checks

The executor now checks Task.isCancelled:

• Before processing every token.
• Before entering Task.sleep.
• Immediately after Task.sleep.

All checks return immediately from the executor.

Commands following a cancelled wait cannot execute.

Because other token dispatch is synchronous on MainActor, Stop cannot interleave between a cancellation check and the associated synchronous dispatch. Any following iteration performs another cancellation check.

12. Stop inside a sequence

The .sm and .stopmedia wait-chain branch now:

1. Clears pending modifier tokens.
2. Calls stopAllMainGridMedia().
3. Cancels all registered sequences, including itself.
4. Returns immediately.

It no longer continues to later tokens.

For:

Sound.wav:.wait 5:.sm:.wait 5:Other.wav

Other.wav cannot execute after .sm.

13. Multiple simultaneous waits

Every wait chain has a separate UUID and Task handle.

Universal Stop copies and cancels every Task in the registry, not merely:

• The newest sequence.
• The oldest sequence.
• The sequence containing .sm.

Two simultaneous waits are both interrupted promptly.

14. New sequences after Stop

Universal Stop clears the old registry.

A subsequent sequence:

• Receives a new UUID.
• Creates a new Task.
• Registers independently.
• Runs normally.

There is no shared cancelled generation or flag that can incorrectly affect later sequences.

15. Registry cleanup safety

Task cleanup removes only its own UUID.

If Universal Stop has already cleared the dictionary:

• removeValue(forKey:) is harmless.

An older Task cannot:

• Clear the registry.
• Remove a newer UUID.
• Cancel a newer Task.
• Decrement an unguarded counter.

16. Keyboard modifier safety

pendingModifierTokens remains local to each executor invocation.

A local defer now clears it for every exit path, including:

• Sleep cancellation.
• Pre-token cancellation.
• Invalid wait.
• Stop command.
• Transport failure.
• Normal completion.

The .sm and .stopmedia branch also clears modifiers before invoking Universal Stop.

No modifier can be transmitted after sequence cancellation or leak into another sequence.
