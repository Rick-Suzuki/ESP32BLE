C. iPad versus iPhone behavior

Both platforms use the same SwiftUI Menu and the same menu-item construction.

They differ through isPad:

• iPad uses full selected labels, such as “screens,” “images,” and “sounds”: lines 44-56.
• iPhone uses abbreviated closed-control labels: “scrns,” “imgs,” and “snds”: lines 47-55.
• iPad uses .body font and 6-point horizontal padding.
• iPhone uses 15-point system font and 4-point horizontal padding.
• iPad closed-control width is 92 points.
• iPhone closed-control width is 74 points.

D. Exact source of the width restriction

The only explicit sizing constraint associated with this Menu is:

.frame(width: isPad ? 92 : 74)

at Set_Screen.swift:841.

There is no width, fixed-size, line-limit, or padding modifier on the opened menu rows themselves. The system controls the Menu popdown geometry.

Therefore, the 92-point iPad label/anchor width is the only source-level constraint that can account for the narrow iPad popdown. The checked item uses Label(mode.selectorTitle, systemImage: "checkmark") at line 824, which needs more horizontal room than the unselected plain Text rows.

E. Truncation, clipping, or compression

Confirmed from source:

• The closed Menu label has .lineLimit(1) at line 833.
• The opened category rows have no .lineLimit, .fixedSize, frame, or truncation modifier.
• No custom clipping is applied to the Menu content.

The source does not explicitly truncate opened row labels. The reported narrow appearance is therefore most likely the native Menu’s sizing in relation to its 92-point iPad anchor/control width, not a custom row-level clipping rule. Physical iPad confirmation is still needed.

J. Layout and compatibility considerations

• The toolbar has a Spacer immediately before the selector at line 571, so the extra 16 points should normally be taken from flexible toolbar space.
• On iPad mini, the toolbar has less horizontal room than iPad Pro, but 108 points remains small and should be lower risk than a larger adaptive redesign.
• Because this is a native system Menu, the exact opened-popdown sizing remains subject to iPadOS behavior and should be checked on iPad Pro, Air, and mini.
• Dynamic Type testing is advisable. The current closed label is single-line and fixed-width, so very large accessibility text could still be constrained even after a 16-point increase.
