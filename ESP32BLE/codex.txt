C. BUTTON DATA MODEL

The grid button model is FunctionKeyEntry: rawLine, sendTexts, alternateDisplayText, buttonColorCode, isBlankPlaceholder, and isHiddenInNormalMode.

Most button-specific data is encoded in rawLine. That includes action/send text, alternate/right display text, color prefix, hidden metadata, SF Symbol display text, file/sound/URL/clipboard commands, and multiline text escaped as text. Multi-cell size is not stored inside the anchor line; it is represented by neighbouring continuation tokens: @@wide and @@block.

D. EXISTING CLIPBOARD SUPPORT

There are two clipboard systems.

Main grid edit clipboard:
@AppStorage("mainGridEditClipboardText") at Main_Screen.swift􀰓.
It stores only one string: entry.rawLine.

Button Editor clipboard:
slotEditorClipboardAction and slotEditorClipboardRight in Soft_Editor_Overlay.swift􀰓.
It copies/pastes editor drafts only, not grid placement/span.

Important limitation: existing main-grid copy does not store button span. A copied 2x1, 2x2, 3x1, or 3x3 button will paste only the anchor raw line unless new clipboard metadata or span-aware paste logic is added.

E. EXISTING UNDO SUPPORT

No general grid/document undo system was found. There is no UndoManager usage or grid operation history. The only undo stack is SmartScriptEditingModel, scoped to Button Editor script text editing.

Popup Undo therefore needs a new small grid-operation history or a wrapper around document slot-line snapshots. Existing undo cannot safely undo move/copy/paste/duplicate/resize/delete.

F. GRID AND MULTI-CELL HANDLING

Multi-cell buttons use an anchor entry plus continuation cells. Rendering skips continuation cells in Main_GridSection.swift􀰓. Shapes are inferred from nearby @@wide and @@block tokens.

Supported spans in current resize logic are [1, 2, 3, 4, 5], where 4 means 2x2 and 5 means 3x3. Collision checks are already present in canSetSlotSpan, hasAvailableBlankSpan, duplicateTargetIndex, and movement planning.

G. PERSISTENCE

Mutations should go through existing closures from ContentView:
updateFunctionKeySlot, duplicateFunctionKeySlot, moveFunctionKeySlot, or existing Main_DocumentActions helpers that call those closures.

Actual saving happens through persistSlotLines() in ContentView.swift􀰓, writing the selected document and reloading in-memory entries. Changes affect the current document immediately.

H. SELECTION STATE

Popup selection is mainGridActionMenuTarget, storing index, button frame, grid dimensions, and probe ID. The grid receives selectedActionMenuIndex. Empty cells are selectable. Continuation cells are not rendered as independent buttons, so they should not normally become popup targets. Document changes/edit-mode off/editor opening dismiss the popup.

Risk: the popup target stores an index and an entry is not stored. Future actions should resolve the current functionKeys[index] at action time to avoid stale data after document changes.

I. IMPLEMENTATION PLAN

Recommended sequence:

Phase 1: Close, Edit, Duplicate, Resize, Delete.
These can call existing helpers with the current selected index and current entry.

Phase 2: Copy and Paste.
First decide whether the clipboard must preserve span. If yes, replace or extend mainGridEditClipboardText with span-aware data before wiring Paste.

Phase 3: Cut.
Implement as span-aware Copy plus existing clear logic. Do not reuse Delete blindly if Delete remains “copy then clear” and Cut needs different user messaging.

Phase 4: Undo.
Add a minimal grid-operation snapshot/history after the basic operations are stable.

J. DESIGN DECISIONS REQUIRED

1. Should Copy/Paste preserve button size/span, or only the anchor button content as today?
2. Should Paste be allowed only into empty cells, or can it replace occupied cells?
3. Should Delete continue copying to clipboard, or should only Cut copy?
4. Should Duplicate use the existing automatic destination rule only, or should a future menu allow choosing destination?
5. Should Undo cover only popup operations, or also existing drag/multi-tap operations?

K. REGRESSION RISKS

Do not change gesture recognition, drag movement, long press, tap timing, popup geometry, diagnostics, document parsing, continuation-cell rules, or Button Editor internals. Resize and Paste are the highest-risk actions because they interact with continuation tokens and occupied-cell checks.
