Manual Play handling

• Play uses a zero-distance DragGesture, not a release-only SwiftUI Button.
• Touch down captures the current MIDI note, velocity, channel, and session, then sends:
MIDI:NOTE_ON:<note>:<velocity>:<channel>
	• Touch up, cancellation, leaving the control bounds, menu close, view disappearance, transport loss, and session replacement all clear local manual state.
	• Valid matching-session releases send:
	MIDI:NOTE_OFF:<captured-note>:<captured-channel>
		• There is no timer for Manual Play.
		• A continuous touch is handled only once, preventing duplicate Note On sends.
		• Velocity 0 sends no Manual Play Note On. A previously captured valid manual note remains active until released.
		
		Preview and Play interaction
		
		• Manual Play stops and cancels any active automatic preview before sending its Note On.
		• Automatic preview does not start while Manual Play is active.
		• Value changes during a manual hold do not alter, retrigger, or release the held note.
		• Turning Preview on or off affects only automatic preview; it does not interrupt Manual Play.
		• After Manual Play ends, Preview remains enabled if it was enabled, ready for later value changes.
		
		Transport and session protection
		
		• Preview and Manual Play remain local to SoftEditorMIDINoteMenu.
		• They use the existing injected authenticated Mac transport.
		• Both active-note records retain note, channel, unique token, and connection-session ID.
		• Cleanup sends Note Off only when the original session is still available and matches, preventing stale Note Off messages from entering a replacement connection.
		• MainMIDIActivationRegistry, main-grid MIDI, CC dispatch, Settings, and editor insertion logic were not changed.
