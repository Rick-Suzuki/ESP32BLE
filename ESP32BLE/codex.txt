Cause confirmed: the one-slide-touch limit currently blocks all other momentary note presses, not just additional sliding.

Exact rejection points

Main_GridSection.swift:
• MIDISlideCoordinator.begin, line 627: rejects any touch while its single stored touch exists.
• MIDITouchCaptureView.touchesBegan, lines 761–766: every momentary note must enter that coordinator. Rejected fingers return immediately without calling onDown.
• Each capture view also stores only one activeTouch and sets isMultipleTouchEnabled = false, preventing two direct fingers on the same button.

The second finger normally does not release the first note; it is simply ignored.

Release points

MIDISlideCoordinator.transition, lines 658–670, releases its previous token before starting the destination note.

cancel/end, capture-view removal, configure changes, and grid lifecycle observers also release that activation. These safeguards should remain, but operate on individual touch records or explicitly cancel all records during a reset.

Additional collision issue

Main_ButtonBehavior.swift:
• MainMIDIActivationRegistry.begin, lines 62–69, permits only one activation per slot.
• release, lines 103–107, immediately sends note-off for the consumed token.

Distinct buttons with the same note/channel can receive separate tokens, but NOTE_OFF contains only note/channel—not a finger identifier. Releasing one can therefore silence the note another finger still holds.

Simply allowing a second press through touchesBegan would restore ordinary chords, but would not fully solve these collisions.

Smallest complete approach

1. Track momentary-note touches individually.
Each touch needs its originating view, current target, and unique ownership token. Enable multiple-touch delivery for eligible note views and process every touch instead of touches.first.

2. Separate sliding ownership from note ownership.
Play every eligible touch-down immediately. Recommend selecting the first finger that leaves its starting button as the sliding finger. Other fingers remain ordinary held-note presses; they do not compete for sliding while that finger owns it.

When the slider ends, do not automatically move another held finger’s note. A subsequent qualifying movement may claim sliding.

3. Release only that finger’s ownership.
A slide transition releases the moving finger’s previous ownership before acquiring its destination. Other held notes remain untouched.

4. Share sounding notes safely.
For momentary notes, maintain ownership counts keyed by connection/session, MIDI channel and note:
• First owner sends note-on.
• Additional owners join without retriggering.
• Each lift removes only its own ownership.
• Last owner sends note-off.

Track slot ownership separately for button highlighting. This handles two fingers on the same button and different buttons producing the same note. Preserve unique tokens and stale-token/session checks; do not give multiple fingers the same releasable token.

5. Preserve reset behaviour.
Lift/cancellation removes the affected touch. Existing global resets, input disabling, screen/session changes, layout changes and disappearance release all momentary owners and clear sliding ownership. Old movement events must not restart playback after reset.

Toggle and CC handling should retain their existing direct paths and token semantics. They should not claim sliding ownership. A momentary note sharing a pitch/channel with a latched note toggle needs explicit coexistence handling so its release cannot silence the toggle.

Likely files

• Main_GridSection.swift: per-touch capture and slider selection.
• Main_ButtonBehavior.swift: momentary ownership counting and token-safe release.
• Main_Screen.swift: activation/highlight integration only where needed.

This requires no layout, geometry, font, scaling or transport-format changes.

Remaining behaviour choice

Recommend no retrigger when entering a note already held by another finger. Its existing velocity remains until all owners release. Retriggering that shared note would affect the holding finger too.
