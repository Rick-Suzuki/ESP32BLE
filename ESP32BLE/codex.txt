3. Exact changes

Added this requirement to each SF Symbol validation guard:

components.count > 1

This requires an explicit colon separator before a value can be recognized or removed as an SF Symbol.

setSmartButtonSFSymbol(_:) was reviewed but required no direct modification. It already uses smartButtonEditorSFSymbolComponents(from:), so it automatically follows the corrected rule.

Examples now behave as follows:

clock
Ordinary text.

stop
Ordinary text.

clock:
SF Symbol without subtitle.

clock:hello
SF Symbol with subtitle “hello”.

Selecting “star” over ordinary text “clock” stores:

star:clock

Selecting “star” over explicitly encoded “clock:hello” stores:

star:hello

Deleting the symbol from “clock:clock” produces ordinary text:

clock

Deleting the symbol from “clock:” produces an empty display value.

Attempting symbol deletion on bare “clock” leaves it unchanged.


4. Ordinary SF Symbol-name text

Confirmed by code path: bare text has only one colon-separated component, so it no longer passes editor or Main Screen SF Symbol recognition.

Words such as “clock” and “stop” remain ordinary text.


5. Explicit selection and deletion

Explicit SF Symbol selection remains supported.

Symbol replacement preserves the existing subtitle.

Deletion only operates when the stored value contains an explicit colon and the prefix is a valid SF Symbol.


6. Existing compatibility

Existing colon-encoded values remain compatible:

clock:
clock:hello
COLOR:clock:
COLOR:clock:hello

No storage model or .screen format was changed.

Legacy bare values such as “clock” now intentionally render as ordinary text.

No .screen files were migrated or rewritten.

8. Remaining risks or limitations

The intended compatibility change remains: legacy symbol configurations stored without a colon now render as ordinary text.
