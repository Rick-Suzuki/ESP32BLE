1. KEY FINDING

The display-mode control is not a Picker, segmented control, menu, or editor-specific selector.

It is a single Main Screen toolbar Button. Each tap calls advanceDisplayMode(), which advances through the modes using FunctionKeyDisplayMode.next().

Consequently, there is:

• No selection binding with missing tags.
• No segmented-control invalid-selection problem.
• No separate iPhone selector.
• No separate iPad selector.
• No button-editor display-mode selector.
• No per-button display-mode value stored in .screen files.

The smallest safe correction would be to change only the cycling sequence so .last advances to .left instead of .both.

The .both case, title, persistence decoding, persistence encoding, and rendering can all remain intact.

8. IMPORTANT CORRECTION ABOUT .SCREEN FILES

The display mode is not serialized inside each button or inside the .screen document contents.

Instead, the current Main Screen mode is stored separately in:

.main_screen_view_mode.cfg

The file is keyed by selectedDocumentName.

Therefore, the relevant compatibility case is not an “All-mode button.” It is a document whose separately persisted Main Screen display mode is .both.

Individual ordinary buttons and widgets do not carry their own .left, .right, .last, or .both value.

No .screen migration or rewriting is needed.

12. OPENING AN EXISTING .BOTH DOCUMENT

Opening or selecting a document whose saved mode is “both texts” performs this sequence:

1. restorePersistedMainScreenModes() reads the document-keyed value.
2. FunctionKeyDisplayMode.init(persistedValue:) returns .both.
3. displayMode becomes .both.
4. savePersistedDisplayMode() writes “both texts” back.
5. Main Screen rendering continues through existing .both branches.
6. The toolbar displays “All.”

No conversion to Command, Button, or Btn Text occurs.

16. OPTION COMPARISON

OPTION A
Simply remove the All segment.

Assessment:

Not directly applicable. There is no segment or option collection to remove.

The equivalent operation would be to skip .both in next().

Complexity:

One transition change.

Compatibility:

Safe if .both decoding and rendering remain untouched.

Existing .both behavior:

Still loads and displays. It becomes unreachable again after the user advances away from it.

Risk:

Very low.

OPTION B
Use a UI-only selection adapter.

Assessment:

Unnecessary.

There is no Picker selection whose bound value must match a visible tag.

An adapter would introduce needless state and increase the chance of accidentally translating .both to another value.

Complexity:

Higher than required.

Recommendation:

Do not use.

OPTION C
Show All only when editing an existing .both button.

Assessment:

The mode is not edited per button, and there is no segmented list of options.

The closest equivalent is the natural behavior already provided by the toolbar Button:

• A restored .both document displays “All.”
• Tapping it moves to Command.
• It cannot be selected again after leaving if .last skips to .left.

This is compatible with the user’s preservation requirement.

Complexity:

No extra conditional UI is needed.

OPTION D
Change only the mode-cycling transition.

Recommended.

Change:

FunctionKeyDisplayMode.next()
Main_BtmRightTxt.swift
Lines 24–35

Future transition:

.left → .right
.right → .last
.last → .left
.both → .left

Keep all four enum cases.

Keep .both.title == “All.”

Keep .both.persistedValue == “both texts.”

Keep .both decoding.

Keep every .both rendering branch.

Complexity:

One source file and one behavioral line.

Reversibility:

Immediate; restoring .last → .both restores the four-mode cycle.

18. EXPECTED LEGACY .BOTH EXPERIENCE

Recommended behavior for a document restored in .both:

• Main Screen continues rendering All mode exactly as before.
• The toolbar temporarily displays “All,” accurately reflecting the active legacy mode.
• Merely opening the document does not change it.
• Saving unrelated button edits does not change it.
• If the user taps “All,” the mode advances to Command and persists “left cmd.”
• Future taps cycle:
Command → Button → Btn Text → Command
• All cannot be reselected through the toolbar or keyboard shortcut.

This is the safest way to reconcile:

• Only three user-selectable modes.
• Preservation of existing .both state.
• No silent conversion.
• No misleading toolbar label.

If “All” must never be visible even while it is actively restored, that would conflict with accurately representing the current mode unless the stored .both value is converted or shown under a misleading label. That is not recommended.
