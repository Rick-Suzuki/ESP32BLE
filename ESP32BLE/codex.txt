ESP32BLE — B2b IMPLEMENTATION REPORT

1. File and lines changed

Modified only:

BLE_KB_Manager.swift

Changed lines 286–293 inside connectToSelectedDevice().

No other functions or files were modified.

2. Skip condition

The selected connection request is skipped only when both conditions are true:

match.peripheral.state == .connecting

probePeripheralIDs.contains(match.id)

No new properties or state variables were introduced. isPendingProbeConnection is a local constant.

3. Other peripheral states

Existing connect behavior remains for:

• .disconnected
• .connected
• .disconnecting
• .connecting without temporary-probe membership

These cases continue using the original:

centralManager.connect(match.peripheral, options: nil)

4. B1 preservation

B1’s didConnect promotion condition remains unchanged:

wasProbe && matchesSelected && matchesActive

Probe membership remains intact when B2b skips the duplicate request, allowing the original pending connection callback to execute B1 promotion.

5. B2a preservation

No B2a properties, guards, discovery callbacks, initialization logic, or cleanup paths were modified.

6. Diagnostic added

When the redundant request is skipped, the existing logging mechanism emits:

SKIPPED DUPLICATE CONNECT

It includes:

• Peripheral UUID
• Selected attempt number
• CBPeripheral.state
• Probe membership
• reason=temporaryProbeAlreadyConnecting

The existing helper supplies the required [BLE-CONNECT-PROBE] and 🐞 prefixes.

The existing selected-connect diagnostic remains unchanged when connect() is requested.

7. Build result

Xcode live diagnostics: No issues found.

Full Xcode project build: Successful.

Build completed in 6.9 seconds with no errors.

8. Remaining risks and limitations

B2b intentionally does not directly promote .connected probes; that remains B2c work.

Pending cancellation and .disconnecting races remain unchanged for B2d.

Validation covered source inspection and compilation. Physical-device BLE testing was not performed.
