Archive handling:

• Recognizes only exact paths shaped like:

templates/Name.template

templates/Name.template.config.json

• Restores both files directly into Documents.
• Does not create Documents/templates.
• Rejects unsupported files inside templates/.
• Rejects orphaned sidecars.
• Rejects leading slash, repeated slash, nested paths, backslashes and invalid template filenames.
• Rejects case-only and canonically equivalent duplicate destinations.
• Preserves malformed sidecar bytes without decoding them.
• Older backups without templates remain valid.

Conflict behaviour:

Replace All:

• If either pair member exists, the complete pair is treated as conflicting.
• Sidecar is published first when supplied.
• Template document is published last.
• A sidecar-less restored template removes an existing stale destination sidecar.
• Both previous destination files are restored if publication fails.

Skip All:

• A conflict involving either pair member skips the entire pair.
• It cannot restore one member while retaining the other from a different version.

Cancel:

• Template pairs are not published during preflight.
• Cancel retains the existing cleanup path and publishes no files.

Rollback behaviour:

• Existing destination bytes and original presence are recorded.
• Incoming bytes are staged and verified in the destination filesystem.
• Destination state is rechecked before publication.
• Final bytes and sidecar presence are verified.
• Failed publication attempts restore the exact previous pair.
• Operation-created files are removed when the corresponding original was absent.
• Ordinary publication failure returns publicationFailedAndRolledBack.
• Failed rollback returns the distinct rollbackFailed critical error.
• Restore reporting counts one failure per logical template pair.

Refresh and navigation:

• Plates discovery refreshes after template restoration attempts.
• Existing selected-template descriptions reload when appropriate.
• Missing selected templates are cleared through the existing refresh logic.
• Templates are never automatically applied.
• Settings category is unchanged.
• Template-only restore does not call loadFunctionKeys and therefore does not change the active screen or navigation history.
• Existing first-imported-screen loading remains unchanged for backups containing screens.
