A. EXECUTIVE SUMMARY

Yes, Copy, Cut, and Paste can share one clipboard mechanism, but the current grid clipboard is not enough for multi-cell buttons.

Current mainGridEditClipboardText stores only one raw anchor line. That preserves button content encoded in rawLine, but it does not preserve dimensions. The safest future implementation is to keep one grid-edit clipboard, but store a small versioned payload containing at least:

• anchor rawLine
• button span or shape
• possibly version metadata

The reader should support the old plain-string clipboard format as a 1x1 legacy value.

E. COPY

Reusable:
• entry.rawLine preserves button content/properties encoded in the slot line.
• slotSpan(...) or buttonShape(...) can capture size.

Gap:
• current Copy only saves entry.rawLine, so it loses dimensions.
• Copy should reject empty/blank cells.
• Copy should not create Undo history.
• Copy can keep popup open and show "Button copied" via renameAlertMessage.

Recommended future Copy:
• validate selected entry is occupied and not continuation
• store one shared clipboard payload { rawLine, span }
• no grid mutation
• no Undo entry

F. CUT

Existing legacy Delete behaves like partial Cut because it writes entry.rawLine to clipboard before clearing, but it loses dimensions.

Reusable:
• popup Delete helper already clears without modifying clipboard.
• clearWideSlot(...) clears full multi-cell footprints.
• Undo snapshot system can record Cut.

Gap:
• need clipboard payload with span before clearing.
• need one successful Undo entry only if the grid changed.
• current legacy Delete clipboard behavior must remain separate from popup Delete.

Recommended future Cut:
• validate occupied selected button
• capture clipboard payload from selected anchor + span
• capture undo snapshot
• clear full footprint
• record Undo only on successful mutation
• leave clipboard containing the cut button even after Undo

G. PASTE

Existing legacy Paste:
• pastes only raw anchor text with updateFunctionKeySlot(index, clipboardEntryText)
• does not preserve dimensions
• does not validate multi-cell footprint
• can only distinguish empty clipboard from not empty

Reusable:
• shape(for:), indexes(...), continuationAssignments(...)
• hasAvailableBlankSpan(...) as a starting point
• restoreFunctionKeySlotLines(...) for one-shot persistence

Gap:
• hasAvailableBlankSpan(...) returns only Bool, so it cannot distinguish “not enough space” from “space occupied.”
• existing Paste is not atomic for multi-cell placement.

Recommended future Paste:
• decode clipboard payload
• selected cell becomes top-left anchor
• validate full footprint first
• build an updated raw slot-line array in memory
• persist once via restoreFunctionKeySlotLines(...)
• record Undo only if restore succeeds and snapshot changed

I. EMPTY-CELL SELECTION

Paste can target empty cells.

Main_GridSection skips only continuation cells with EmptyView() at lines 140-143. Ordinary empty cells still render through gridButtonView(...) and have frames/gestures. The popup already opens on empty positions.

Copy/Cut should reject empty cells. Paste should allow them.

J. UNDO INTEGRATION

Current Undo system is suitable:
• snapshots are raw slot-line arrays
• entries are document-scoped
• limit is 20
• restore uses restoreFunctionKeySlotLines(...)
• history clears on selectedDocumentName change
• failed restore preserves the Undo entry

For future operations:
• Copy: no Undo
• Cut: capture before snapshot, mutate, record if successful
• Paste: capture before snapshot, mutate, record if successful

Undo should not alter clipboard.

K. CROSS-SCREEN CLIPBOARD

Current mainGridEditClipboardText is AppStorage, so it survives:
• screen/document changes
• app restarts

That supports cross-screen clipboard behavior. However, it needs an extended payload to preserve size across screens.

Undo history already clears on document changes; clipboard should not.

M. ATOMICITY

Safest future sequence:

Copy:
• no mutation; just write clipboard payload

Cut:
• validate source
• build clipboard payload
• capture undo snapshot
• clear footprint
• if clear succeeds, write clipboard and record Undo
• if clear fails, do not record Undo

Paste:
• decode clipboard
• validate boundary and occupancy before mutation
• build complete updated slot-line array
• persist once via snapshot restore closure
• record Undo only after successful restore

Avoid using repeated updateFunctionKeySlot(...) for Paste if possible, because multi-cell placement should be one logical persistence operation.

N. RISKS

Main risks:
• old clipboard plain strings are spanless
• changing mainGridEditClipboardText format could break legacy paste unless backward-compatible
• hasAvailableBlankSpan(...) cannot provide required failure messages as-is
• repeated per-cell mutation can partially apply changes if persistence fails mid-operation
• continuation markers must not be copied as independent buttons
• Cut must not accidentally reuse popup Delete in a way that skips clipboard
• Undo must restore grid only, not clipboard
• cross-screen Paste must validate against the destination screen’s grid dimensions
