SPEECH RECOGNITION

New routing path:

recognized speech
-> matchingSpeechEntry(for:)
-> bluetoothSendTexts(for:)
-> sendKeyboardOutputTokens(...)
-> ESP32/BLE or MacConnectionManager

applyRecognizedSpeech(_:) no longer checks BLE or calls ble.sendLine directly.

sendModifierFunctionKey(_:) now routes ["ct", "sh", "op", "cm", functionKey] through sendKeyboardOutputTokens(...). No caller was added.

SMART EDITOR TEST

testEditingSlotText() non-wait output now calls sendKeyboardOutputTokens(..., respectsButtonMode: false).

Mac mode no longer requires BLE for this test path. Wait behavior and parsing were preserved.

SETTINGS TEXT SEND

sendEnteredText() now follows outputModeRawValue.

ESP32 selected:
ca, if enabled, still sends through ble.sendLine("ca")
text still sends through ble.sendString(trimmedText)

Mac selected:
["ca", text] or [text] goes through macConnection.sendKeyboardTokens(...)

ESP32 keyboard timing configuration remains BLE-only and was not changed.

OUTPUT MODE SWITCHING

Press ESP32:
selects ESP32 output mode
calls macConnection.stop()
does not auto-connect BLE
leaves ESP32 device selection/connection to the device rows

Press Mac:
selects Mac output mode
calls ble.disconnect()
calls macConnection.start()

Pressing the already-selected mode does not disconnect that mode. Pressing Mac while already in Mac mode may call start(), which is safe and preserves connection establishment.

Deliberate Mac disconnect:
MacConnectionManager now tracks an intentional stop. Browser failure, connection cancellation/failure, and send-completion errors do not restart search while deliberately stopped. Accidental/network loss still uses existing restart behavior.

BLE reconnect:
Selecting Mac calls ble.disconnect(). BLE scanning may continue through existing BLE manager behavior, but this does not immediately reconnect unless the existing device-selection flow requests a connection.

DISCONNECT BUTTON

Removed the explicit ESP32 disconnect UI button: the red xmark button above/near the ESP32 device area in SettingsAvailableDevicesPanel.

BLEKeyboardManager.disconnect() remains intact and is still used internally when switching to Mac mode.

BUTTON COLORS

Inactive mode buttons keep the existing gray appearance.

Grid edit mode still pulses, now using the selected transport’s connected color.
