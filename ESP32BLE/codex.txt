Previous Play handling

• Play previously used a SwiftUI zero-distance DragGesture.
• Its gesture-state timing could defer the begin callback until release on the reported device.

New Play touch handling

• Replaced only the Play interaction with ManualMIDINotePlayControl, a small UIViewRepresentable wrapping UIButton/UIControl.
• The visual still displays “Play” and pianokeys.inverse horizontally.
• UIKit target events are now:
• touchDown: begin Manual Play.
• touchUpInside: end Manual Play.
• touchUpOutside: end Manual Play.
• touchCancel: end Manual Play.
• touchDragExit: end Manual Play immediately when leaving bounds.
• View dismantling also calls the same guarded end path.

MIDI event sequence

• touchDown captures the current calculated note, velocity, channel, and authenticated session.
• It stops an active automatic preview, then sends one MIDI:NOTE_ON:<note>:<velocity>:<channel>.
	• No timer is scheduled for Manual Play.
	• While held, existing local active-manual state blocks duplicates and automatic preview.
	• Release or cancellation sends one matching MIDI:NOTE_OFF:<captured-note>:<captured-channel>, only if the original session remains current.
		• Velocity 0 continues to send no Manual Play Note On.
		
		Cancellation and cleanup
		
		• Menu close, view disappearance, output loss, and connection-session replacement use the existing reset/transport-cleanup path.
		• Repeated end events are harmless because Manual Play clears its active record before attempting Note Off.
		• No stale Note Off is sent to a replacement connection session.
		• Preview enable/disable continues not to interrupt an active Manual Play note.
