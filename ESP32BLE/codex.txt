C. FIRST CONFIRMED DIFFERENCE

Both commands are correctly recognized by:

targetDocumentNameForSendText(_:)

Both resolve to:

home.screen

The first relevant difference occurs after that function returns.

targetDocumentNameForGridEntry(_:) discards the resolved value and returns the original command string:

home  → original “home” passed to selection
.home → original “.home” passed to selection

The undotted form succeeds only because ContentView’s legacy .txt-to-.screen fallback happens to match “home” with home.screen.

The dotted form fails because the leading period remains part of the filename base.

D. WHY “.home” BECOMES “.home.txt”

ContentView.swift
canonicalDocumentFileName(from:), lines 2755–2764

The logic is:

• Preserve names already ending in .screen or .txt.
• Otherwise append .txt.

The raw value passed to it is incorrectly “.home”, not “home.screen”.

It therefore produces:

.home.txt

The filename-resolution code is behaving according to its existing general rules. It is not the source of the defect.

E. TARGET RESOLVER USAGE

targetDocumentNameForSendText(_:) is called and returns the correct result:

home.screen

Its result is used correctly in these locations:

• bluetoothSendTexts(for:), lines 413–433, to prevent document commands from reaching BLE.
• runWaitChainCommandTokens(...), lines 532–539, which passes the resolved value directly to document selection.

Its result is not used correctly in:

targetDocumentNameForGridEntry(_:), lines 697–700

That function uses it only as a Boolean predicate and returns the matching original string.

The ordinary Main Screen button path uses this faulty wrapper.

G. ROOT CAUSE

Confirmed root cause:

targetDocumentNameForGridEntry(:) returns the original matching sendText instead of the resolved result from targetDocumentNameForSendText(:).

Current conceptual behavior:

Find a sendText whose resolved target is nonnil, then return the sendText.

Required behavior:

Resolve each sendText and return the first nonnil resolved document name.

The W2C .home recognition itself is correct.

H. SMALLEST SAFE CORRECTION

Modify only:

Main_ButtonBehavior.swift
targetDocumentNameForGridEntry(_:), lines 697–700

Recommended implementation:

Return the first nonnil result produced by targetDocumentNameForSendText(_:), rather than returning the original matching sendText.

Conceptually:

entry.sendTexts.compactMap(targetDocumentNameForSendText).first

Expected results:

home
→ targetDocumentNameForSendText returns home.screen
→ selectDocumentNamedFromGrid receives home.screen

.home
→ targetDocumentNameForSendText returns home.screen
→ selectDocumentNamedFromGrid receives home.screen

Explicit .screen and legacy .txt document names remain unchanged because targetDocumentNameForSendText(_:) already returns those original filenames.

Do not modify selectDocumentNamedFromGrid(_:) or canonicalDocumentFileName(from:).
