ESP32BLE — WIDGET-002 / W2A CORRECTION REPORT

1. Root cause

The W2A helper validated only undotted commands. Therefore, “.out 4 1” and “.pwm 1 2 3” produced no default fallback, leaving Right mode blank.

2. File and function modified

File:
ESP32BLE/ESP32BLE/Scrns/Main_Screen/Main_ButtonBehavior.swift

Function:
commandDefaultLabel(for:)

3. Generated right-hand text

For a single dotted command, the helper:

• Removes exactly one leading period.
• Uses the existing numeric validator on the resulting text.
• Returns the complete text, preserving arguments, spacing, order, values, and capitalization.

Results:

.out 4 1 → out 4 1
.pwm 1 2 3 → pwm 1 2 3

Invalid numeric forms receive no special fallback.

4. Explicit text

Explicit right-hand text still returns before fallback processing and therefore takes precedence.

5. Dotted command execution

Dotted OUT/PWM commands are not currently recognized by the execution normalizer.

The executable normalization syntax remains:

out 4 1
pwm 1 2 3

Dotted forms fall through as unchanged ordinary BLE text rather than being normalized as OUT/PWM commands.

6. Execution and BLE

No command recognition, normalization, execution, or BLE transmission code was changed.

Navigation mappings and unrelated buttons remain unchanged.

7. Build result

The ESP32BLE project built successfully with no errors.

No application, simulator, device, or ESP32 hardware testing was performed.
