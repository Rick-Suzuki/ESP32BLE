B. Current command storage and safest extraction

FunctionKeyEntry contains:

• rawLine: original stored line, except blank-placeholder input "_" and empty input become rawLine == "".
• sendTexts: parsed action tokens used for execution.
• alternateDisplayText: optional right-side display field.
• isBlankPlaceholder and isHiddenInNormalMode flags.

The stored format is:

• Command only: ".sp"
• Command plus display: ".sp::Play"
• Empty command plus display: "::Play"
• SF Symbol plus subtitle: ".sp::play.fill:Play"
• Hidden entry: command/display fields plus the hidden metadata token on the right side.

The first "::" is the command/display boundary. The safest diagnostic command extraction is therefore the exact substring of entry.rawLine before its first "::"; if no "::" exists, use rawLine itself.

Do not use sendTexts for [ESP-COMMAND]. It has already been parsed: it trims content, splits ordinary colon-separated command chains, expands compact modifier syntax, and preserves HTTP/HTTPS specially. It does not reliably represent the original stored command field.

This extraction supports:

• "::Play" -> no content.
• ".sp::Play" -> ".sp".
• "Hello" -> "Hello".
• ".sp:.ret::Play" -> ".sp:.ret", once, before tokenization.
• Hidden entries -> original command only; hidden metadata is to the right of the first separator.
• Blank placeholders -> no content when an ordinary activation is accepted.

A literal "::" cannot be represented as part of the command field under the existing file grammar; it is already the display separator.

G. Empty, multiline, and multi-command handling

Recommended output policy:

• Empty or whitespace-only command field:
🐞 [ESP-COMMAND] no content

• Nonempty command:
🐞 [ESP-COMMAND] <original escaped command field>

Use the existing ESPOutputProbe.escapedString(_:) helper at Main_ButtonBehavior.swift:389-410. It already escapes:

• Backslash
• Double quote
• Newline
• Carriage return
• Tab

This keeps one activation to one console line while preserving the original stored command content for diagnostics.

For multiple stored commands, print one [ESP-COMMAND] line containing the original pre-parser field, such as .sp:.ret; do not print one command diagnostic per token.

Identical button labels are not a logging ambiguity for this purpose because the log describes the selected FunctionKeyEntry’s stored command. The existing [ESP-BUTTON] metadata identifies the displayed symbol/text alongside it.

H. Independence from output and transmission

The proposed [ESP-COMMAND] can be entirely independent of:

It would therefore log empty commands, internal-only commands, sound/file/navigation commands, connection failures, and commands producing no keyboard output.

The current generic physical callback is only reached after the ordinary button passes edit-mode, long-press, and bleSendEnabled guards. The speech location is reached only after a unique grid-button match.
