3. Shared universal stop implementation

stopAllMainGridMedia() was added at Main_ButtonBehavior.swift:1625.

It synchronously calls:

• stopSpokenGridText()
• stopMainGridSoundPlayback()
• mainGridAmbientSoundState.stopPlayback()

All three user-facing routes call this same helper:

• .sm
• .stopmedia
• Square toolbar Stop button

No new audio manager, queue, timer, or asynchronous stop mechanism was introduced.

4. .sm recognition

isStopMediaCommandText(_:) was added at Main_ButtonBehavior.swift:1616.

It recognizes .sm only after trimming surrounding whitespace and lowercasing the complete token.

It does not use prefix matching, so these do not match:

• .small
• .smoke
• .sm extra

5. .stopmedia recognition

The same shared predicate recognizes .stopmedia as an exact complete command.

It does not match:

• .stopmediaextra
• .stopmedia extra

6. Case-insensitive matching

The predicate lowercases the trimmed command before comparison.

These are therefore supported:

• .sm
• .SM
• .stopmedia
• .STOPMEDIA
• Mixed-case equivalents

7. .stop stopwatch preservation

The existing .stop and .stopwatch widget parsing was not modified.

They remain stopwatch widget commands.

8. Manual button execution

Main_ButtonBehavior.swift:323–325 now detects either stop alias after existing .wait routing.

A matching manual button:

• Calls stopAllMainGridMedia().
• Returns immediately.
• Does not execute the existing keyboard-output path.
• Preserves the existing button-mode guard and click-feedback behavior.
• Preserves Edit Mode behavior.

9. .wait execution

Main_ButtonBehavior.swift:524–528 handles stop aliases inside runWaitChainCommandTokens(...).

The branch:

• Clears pending keyboard modifier tokens.
• Calls the shared universal stop helper.
• Continues processing the remaining command tokens.

It does not return from or cancel the sequence.

Therefore a sequence such as:

Sound.wav:.wait 5:.sm:.wait 2:Other.wav

continues through all five operations in order.

Wait duration handling, Task.sleep, concurrency, and cancellation behavior were not changed.

10. Speech-triggered execution

SR_Support.swift:72–75 now detects stop aliases after the existing wait-chain branch and before speech-specific command extraction.

It:

• Calls the shared universal stop helper.
• Returns immediately.
• Prevents duplicate processing or transport output.

Speech matching, feedback, recognition lifecycle, microphone handling, and auto-off behavior were not changed.

Speech entries containing .wait continue to use the existing wait-chain executor, which now recognizes the stop aliases.

19. Speech request-ID protection

A MainActor-owned state value was added:

speechPlaybackRequestID

Main_Screen.swift:864

Every accepted speech synthesis request now:

1. Stops and invalidates the preceding request.
2. Installs a new UUID.
3. Starts audio-session activation.
4. Checks that UUID after activation.
5. Speaks only if it remains current.

The validation is at Main_ButtonBehavior.swift:760–762.

20. Stale asynchronous request safety

An older speech request can no longer stop newer speech after activation because the old stopSpokenGridText() call was moved before the asynchronous activation begins.

If Stop or a newer speech request changes the UUID while activation is pending, the older Task returns silently before creating or speaking its utterance.

Ordinary and ambient stale-request protection continues using their existing request identifiers.
