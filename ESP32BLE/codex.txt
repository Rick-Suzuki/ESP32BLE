Failure point:

1. Files opens in Command and captures:
   • sessionID: current softEditorAccessorySessionID
   • slot: editingSlotIndex
   • document: selectedDocumentName
   • editor: .command
   • first-responder state
   • current smartPasteTarget.textView is only used to confirm a target exists

2. Command insertion succeeds through:
   • insertSoftEditorFileName
   • live smartPasteTarget.textView reacquisition
   • insertSoftEditorAccessoryText
   • insertSmartActionTextAtSelection

3. Switching to Button runs the Button editor onBeginEditing callback:
   • invalidateSoftEditorAccessorySession()
   • smartPasteTarget.activate(.button, textView: textView)

4. The session ID changes when Button begins editing.

5. Button insertion still uses the old filesInsertionContext captured in Command.

6. The first failing guard is:
context.sessionID == softEditorAccessorySessionID

The retained Command session ID no longer matches the new Button session ID.

7. Returning to Command runs:
   • invalidateSoftEditorAccessorySession()
   • smartPasteTarget.activate(.command, textView: textView)

This creates another new session ID, while the Files menu still retains the original Command context. The next Command insertion fails the same session check.

Relevant paths:

• Command activation: Main_Screen.swift:3955-3957
• Button activation: Main_Screen.swift:4420-4422 and 4443-4445
• Session invalidation: Main_Screen.swift:1373-1375, 3877, 3956, 4421 and 4444
• Files context capture: beginSoftEditorFilesMenu()
• Files insertion validation: insertSoftEditorFileName()
• Retained menu context: SoftEditorAccessoryPalette.filesInsertionContext and SoftEditorAccessoryBar.filesInsertionContext

The live UITextView reacquisition fix is active, but it is reached only after the session and editor guards pass. It cannot correct this failure because the stale session is rejected first.

The retained context is not cleared or replaced when switching editors. The Files menu calls onFiles() only when Files is initially opened. Each later file selection reuses the original context.

Additional cross-editor failure:

Even if the session check were bypassed, this guard would reject a Command context while Button is active:

context.editor == smartPasteTarget.editor

Recommended smallest safe design:

• Preserve the original Files context’s slot and document identity.
• At each file selection, reacquire the current smartPasteTarget editor, current UITextView, current session ID and live selection.
• Validate the original slot/document against the current slot/document.
• Treat the current active editor and current session as authoritative for that selection.
• Retain window and selection-bounds validation.
• Then insert through the existing Command/Button helper.

This allows intentional Command/Button switching while still rejecting insertion into a changed slot or document.
