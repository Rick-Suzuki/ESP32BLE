2. Simple-sound classification

Added isSimpleOrdinarySoundEntry(_:) at Main_ButtonBehavior.swift:1093.

An entry qualifies only when:

• entry.sendTexts.count == 1
• targetSoundRequestForSendText(_:) returns a valid ordinary sound request

The existing parser remains the sole authority for filenames, extensions, snd prefixes, and volume.

Ambient, wait, compound, invalid-volume, keyboard, speech, and widget commands do not qualify.


3. Gesture routing

MainScreenGridSection receives:

• isSimpleOrdinarySoundEntry
• onSimpleOrdinarySoundSingleTap
• onSimpleOrdinarySoundDoubleTap

Only qualifying buttons outside Edit Mode enter the new gesture branch.

Other buttons continue through their existing Button or interactive-widget paths.


4. Single-tap behaviour

handleSimpleOrdinarySoundSingleTap(_:index:) implements:

• Stopped: starts from the beginning
• Preparing: records a pending pause
• Playing: calls AVAudioPlayer.pause()
• Paused with a prepared player: calls play() to resume
• Paused while still preparing: changes the intent back to playing

Existing click feedback and disabled-mode guards remain active.


5. Double-tap behaviour

handleSimpleOrdinarySoundDoubleTap(_:index:) starts a new ordinary sound request through playMainGridSound(...).

This:

• Stops and replaces the current ordinary player
• Invalidates pending preparation
• Prepares a new player off-main
• Starts from time zero

It works while stopped, preparing, playing, or paused.

7. Button ownership identity

Ownership uses the project’s existing document-and-slot identity pattern:

selectedDocumentName#index

Two buttons containing the same filename therefore remain distinct owners.

Changing documents or selecting a different slot produces a different identity.


8. Pause/resume implementation

Pause uses the existing soundEffectPlayer.pause().

Resume uses the same retained AVAudioPlayer and calls play(), preserving currentTime.

No additional ordinary player or playback manager was introduced.

A paused sound keeps ordinarySoundActive true, so Universal Stop remains green.


9. Preparation-time tap handling

When the owning button is tapped during preparation:

• Phase changes from preparing to paused.
• Activation and background preparation continue.
• The prepared player is retained.
• play() is not called.
• The player remains paused at time zero.

A subsequent tap before preparation completes changes the phase back to preparing, allowing playback to begin when preparation finishes.

A double tap installs a new request UUID, invalidating the older preparation.


10. Natural completion handling

The existing MainGridSoundPlaybackDelegate still reports natural completion.

Its request-ID-protected callback now also clears:

• Gesture owner
• Gesture request
• Gesture request ID
• Playback phase

A stale player callback cannot clear a newer request.


11. Universal Stop integration

stopMainGridSoundPlayback() now clears all ordinary gesture state in addition to its existing behaviour.

Universal Stop therefore:

• Invalidates pending ordinary preparation
• Stops and releases the player
• Clears pause/resume ownership
• Resets the phase to stopped
• Clears ordinarySoundActive

The ambient, speech, and wait cancellation operations remain intact.


12. Other ordinary-source replacement behaviour

playMainGridSound(...) remains the shared playback path.

Its new gesture parameters default to nil. Consequently, every non-gesture caller automatically clears previous gesture ownership after validating the new filename and volume.

This covers:

• Compound commands
• Wait sequences
• Speech-triggered commands
• Keyboard/editor testing
• Timer-completion sounds

A missing file or invalid volume returns before clearing the existing sound or gesture state, preserving prior behaviour.
