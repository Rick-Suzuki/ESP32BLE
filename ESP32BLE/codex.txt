 Settings currently stored in ScreenConfig

• schemaVersion
• fontSize
• grid.rows
• grid.columns
• backgroundImageName
• backgroundOpacity
• gridOpacity

Current model details:

• ScreenConfig is Codable and Equatable.
• ScreenConfig.Grid is Codable and Equatable.
• schemaVersion defaults to 1.
• fontSize defaults to 20.0.
• backgroundOpacity defaults to 0.5.
• gridOpacity is optional.
• backgroundImageName is optional.
• grid row and column values are clamped to at least 1.
• backgroundOpacity and gridOpacity are clamped to 0...1.

2. Comparison against required portable document configuration

font size

• Present.
• Field: fontSize.
• Type: Double.
• Concern: default is duplicated as ScreenConfig.defaultFontSize = 20.0 rather than sharing ContentView’s defaultDocumentFontSize.

brightness

• Missing.
• There is no document-level brightness field.
• If brightness means the smart editor color brightness slider, it should not be stored in ScreenConfig because current button color is already stored as final hex text in the txt file.
• If brightness means a screen-level image/display brightness setting, add a dedicated optional field.

opacity

• Partly present.
• Present: backgroundOpacity.
• Present but unused/ambiguous: gridOpacity.
• Missing if needed: separate button background opacity or screen overlay opacity.
• Recommendation: clarify gridOpacity before connecting UI. The current app has mainGridBackgroundOpacity, which behaves more like button background opacity than “grid” opacity.

button width

• Missing.
• Should not be added as actual pixel width.
• Button width is calculated from device size, columns, spacing, and current layout.
• Portable config should store grid/layout intent, not rendered dimensions.

button height

• Missing.
• Should not be added as actual pixel height.
• Button height is calculated from device size, rows, spacing, safe area, and toolbar state.

grid/layout

• Partly present.
• Present: grid.rows and grid.columns.
• Button order and large-button layout remain in txt through line order, @@wide, and @@block.
• Missing only if future UI supports additional layout settings such as spacing, layout mode, or orientation-specific layouts.

images

• Partly present.
• Present: backgroundImageName.
• Good: filename-based storage is portable.
• Missing optional future fields:
   • backgroundImageMode, such as fill/fit/stretch
   • backgroundImageAlignment, if positioning becomes user-configurable

PDFs

• Missing.
• If PDFs are only referenced by button commands, they should stay in txt.
• If a screen can have a document-level PDF assignment, add pdfName.

sounds

• Missing.
• If sounds are only referenced by button commands, they should stay in txt.
• If a screen can have a document-level ambient/default sound, add ambientSoundName or defaultSoundName.

future source types

• Missing.
• schemaVersion supports future migration, but there is no field for future source references.
• Add only if there is a known use case. Otherwise keep the model simple.

3. Missing configuration fields to consider before connecting UI

Recommended to add before connecting UI:

• buttonBackgroundOpacity: Double?
Better name than gridOpacity if the current mainGridBackgroundOpacity is meant to become screen-specific.

• screenBrightness: Double?
Only if brightness is a real screen-level appearance setting.

• backgroundImageMode: String?
Optional future-proof field if image rendering mode may become configurable.

• pdfName: String?
Only if there is a document-level PDF association.

• ambientSoundName: String?
Only if there is a document-level sound association.

Recommended not to add:

• buttonWidth
• buttonHeight

Reason:
Those are calculated layout results, not portable document settings.

4. Recommended final ScreenConfig structure

Recommended final fields:

• schemaVersion: Int
• fontSize: Double
• grid: ScreenConfig.Grid
• backgroundImageName: String?
• backgroundOpacity: Double
• buttonBackgroundOpacity: Double?
• screenBrightness: Double?
• backgroundImageMode: String?
• pdfName: String?
• ambientSoundName: String?

Recommended nested grid fields:

• rows: Int
• columns: Int

Keep out of ScreenConfig:

• button action text
• button display text
• button order
• button colors
• hidden state
• @@wide and @@block markers
• selected document
• BLE settings
• keyboard preferences
• TTS settings
• navigation history
• editor state
• runtime state
• actual button pixel width
• actual button pixel height

Main recommendation:

• Keep fontSize, grid.rows, grid.columns, backgroundImageName, and backgroundOpacity.
• Replace or supplement gridOpacity with buttonBackgroundOpacity before wiring UI.
• Add screenBrightness only if brightness is intended as a screen-level visual control.
• Add PDF/sound fields only for document-level associations, not for button command references.
