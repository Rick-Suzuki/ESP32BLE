• Yes, if selectedDocumentFileURL exists and is a .screen file.

Can it export multiple screens?

File extension produced:

Is the original document modified?
• Yes, potentially.

• saveCurrentDocumentText() writes documentEditorText to the loaded file, lines 1310-1317 and 1347-1354.
• The export itself does not modify the original config unless saveCurrentDocumentText or related state already does.

Does it include associated images/sounds/PDFs?
• No.

Does it include settings?
• It includes the per-screen .config.json only.
• If an existing valid config exists, it uses it.
• Otherwise it generates default config data for the exported package.
• It does not include AppStorage settings like selected background image, selected sound, timing, TTS voice/rate, output mode, etc.

Does it use a share sheet or file exporter?
• It uses UIDocumentPickerViewController(forExporting:asCopy:) through SettingsSingleFileExportPicker.

• makeSingleFileExportURL() falls back to documentEditorText and singleFileExportDisplayName.

• Result would be a generated .screen file inside Document.zip, with generated default config.

5. EXACT RESTORE BACKUP BEHAVIOUR

Action path:
Restore Backup -> confirmation alert -> beginRestoreAllFiles()
beginRestoreAllFiles() sets mode .allFiles.
.fileImporter allows ZIP only.

Accepted archive formats:
• .zip only.

Expected ZIP structure:
• Must be a full archive as defined by fullArchiveStructure().
• Required:
   • Archive.json
   • at least one content folder entry under Screens/, Configs/, Text/, Images/, Sounds/, or PDFs/
• Archive entries must use the custom supported ZIP subset:
   • local file headers
   • compression method 0 only
   • no data descriptor flag
   • compressed size must equal uncompressed size
• Standard compressed ZIPs using deflate are rejected as unsupported.

Merge or replace?
• It merges into the Documents directory.
• It does not delete files that are absent from the archive.
• Existing files with the same name are replaced automatically.

Duplicate filename behaviour:
• In .allFiles mode, applyPendingImportConflictIfNeeded() automatically calls importReplacingExistingFile().
• No per-file conflict prompt is shown for restore.
• Existing target is removed first, then imported.

Can existing files be deleted?
• Existing files with matching names can be deleted/replaced.
• Files not present in the archive are not deleted.

Are settings restored?
• Per-screen .config.json files are restored if present/valid.
• AppStorage preferences are not restored.
• Selected background/sound/PDF preferences are not restored as settings, though the files themselves may be restored.

Active screen affected?
• If a screen document is restored/imported, firstImportedDocumentURL is loaded through loadFunctionKeys().
• First restored image/sound/PDF may become selected only if no current selection exists, since importListMode is nil for restore.

Confirmation requested?
• Yes for Restore Backup.
• No if a full archive ZIP is selected via Import Screens.

Malformed archives:
• If not full archive: "Couldn't import all files: ..." after fileReadCorruptFile.
• Unsupported compression/data descriptor: unsupported scheme error.
• Entries outside expected folders or with invalid names are ignored.
• Invalid configs are copied, decoded, then removed and treated as failure if decoding fails.

Partial restore possible?
• Yes.
• Restore processes entries sequentially.
• Failures increment failedFileCount but do not necessarily roll back previous successful imports.
• This creates partial-restore risk.

Data-loss risk:
• Restore replaces same-name files automatically after one global confirmation.
• It removes existing files before importing replacements.
• If import of the replacement then fails, the old file may already be gone.
• Import Screens can trigger full archive restore behavior without the restore confirmation if the ZIP has full archive structure.

14. DATA-LOSS OR COMPATIBILITY RISKS

Data-loss risks:
• Restore replaces same-name files automatically.
• Existing file is removed before replacement import is completed.
• Partial restore is possible; no rollback exists.
• Import Screens can process a full archive ZIP and enter allFiles mode without the Restore Backup confirmation.
• Export operations save the currently loaded editor text before exporting, which can modify existing documents.

Compatibility risks:
• ZIP parser supports only stored/uncompressed ZIP entries.
• ZIPs created by common tools with deflate compression may fail restore.
• Full archive detection requires Archive.json plus archive folder content.
• Unsupported files in Documents are excluded from backup.
• AppStorage settings are not included, so restored app state may not match original app state.
• Direct legacy .txt import is not supported by Import Screens, despite legacy .txt export/restore support.
