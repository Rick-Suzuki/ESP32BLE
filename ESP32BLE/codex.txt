3. Settings → Main behavior

The Main toolbar still calls saveAndReturnToMain().

saveAndReturnToMain(using:) now:

• Uses documentEditorText or its supplied text parameter.
• Calls the existing conflict-aware saveCurrentDocumentText(_:).
• Receives a DocumentSaveResult from the existing F2B.2 mechanism.
• Calls returnToMain() only when allowsDocumentTransition is true.
• Never writes directly to disk.
• Never calls saveSelectedDocumentAndReload(_:) anymore.

4. DocumentSaveResult handling

unchanged:

• No additional write.
• Settings dismisses.

saved:

• The protected save completed successfully.
• Settings dismisses.

reloadedFromDisk:

• The editor and baseline contain the authoritative disk contents.
• Settings dismisses.

conflict:

• No write occurs.
• Settings remains open.
• Local editor contents are preserved.
• The existing “File Changed Externally” alert is presented.

missing:

• The file is not recreated.
• Settings remains open.
• Local editor contents are preserved.
• The existing “File Removed” alert is presented.

failed:

• Settings remains open.
• Local editor contents are preserved.
• The existing failure alert remains responsible for reporting the error.

5. Blocked-result preservation

F2B.2 previously remembered only that saving was blocked. It could not distinguish a conflict from a missing file on a later Main-button press.

The state now retains the actual DocumentSaveResult:

• conflict remains conflict.
• missing remains missing.

Pressing Main again reuses the same alert infrastructure and presents the appropriate message without repeating the disk write attempt.

No second conflict-detection system was introduced.
