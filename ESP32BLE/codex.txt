5. Existing Back Delete implementation

Main_Screen.swift:5028-5045, deleteSmartEditorBackward(), is presently unused except by inactive smartCommandEditorRow.

It is the appropriate reusable deletion path:

• Requires an editing slot.
• Requires a registered smartPasteTarget.textView.
• Requires that text view to be attached to a window.
• Requires text-view contents to match the current target model.
• Uses the current smartPasteTarget.editor.

For Command:
• Reads the live UITextView.selectedRange.
• Writes it to smartScriptEditingModel.
• Calls SmartScriptEditingModel.deleteBackward().
• Syncs the result through smartActionTextBinding.

Main_SmartScriptEditingModel.swift􀰓:
• Deletes selected text when selection length is nonzero.
• Does nothing at location zero.
• Deletes one composed-character sequence before the cursor.
• Updates the selection to the deleted range’s start.
• Is Unicode-safe for composed characters and emoji.

For Button:
• Calls the active registered UITextView.deleteBackward() at Main_Screen.swift:5042-5043.
• SmartPreviewTextView.Coordinator.textViewDidChange at Main_SmartEditorTextInputs.swift:302-306 synchronizes edited text and selection.
• syncTextAndSelection at lines 542-553 updates the binding and cursor range.

The Button branch relies on UIKit’s UITextView deletion semantics. It does not manually slice Unicode text, which avoids a source-level UTF-16 indexing defect. Emoji behavior still requires device testing.

6. Command/Button safety

deleteSmartEditorBackward() has the required current-target checks before it deletes. It will return without changing text if there is no selected slot, no target text view, a detached view, or a text/model mismatch.

It uses smartPasteTarget.editor, so it selects Command or Button according to the actively registered editor. It does not use the legacy overlay’s activeEditorField.

The currently visible "xmark" action has none of these protections and only clears Command text.
