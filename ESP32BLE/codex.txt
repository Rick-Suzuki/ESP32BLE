C. MIDI physical press observation

Specialized MIDI buttons now log from the existing MIDITouchCaptureView touch-down path.

Coverage:

• MIDI momentary notes.
• MIDI note toggles.
• Explicit MIDI Note Off buttons.
• MIDI CC hold.
• MIDI CC toggle.
• MIDI slide-entered note buttons.

The callback occurs before MIDI registry, transport, toggle-state, Note On, Note Off, or connection-result processing.

MIDI finger release, cancellation, registry changes, Note Off generated by release, and transmission callbacks do not log diagnostics.

D. Ordinary sound observation

Ordinary sound continues using its existing exclusive single/double TapGesture implementation.

After its existing physical gesture callback passes the unchanged bleSendEnabled guard, it calls the existing Stage 1 helper before entering the single- or double-tap sound handler.

No playback behavior, sound-file lookup, gesture timing, or audio state was changed.

E. Ambient sound observation

Ambient widgets retain their existing gestures and playback logic.

The originating FunctionKeyEntry is forwarded through a diagnostic-only closure from MainScreenButtonLabelView to MainGridAmbientSoundWidgetView. The existing helper is called before ambient toggle/restart playback processing.

No main-grid-mode restriction, volume parsing, asynchronous playback handling, or widget interaction behavior was changed.

F. Double-tap diagnostics

Limitation: existing ordinary-sound and ambient gestures expose a completed single-tap or double-tap result, not individual touch-down events.

Therefore:

• Single tap: one diagnostic pair.
• Double tap: one diagnostic pair for the completed double-tap gesture.
• Triple ambient tap: no diagnostic pair, because it remains a deliberate no-op.

I did not add competing touch recognizers, change recognition timing, or generate artificial duplicate log pairs for a double tap.

G. MIDI slide-entered keys

Yes. A note entered through the existing MIDI slide coordinator produces a diagnostic pair when the current touch handling begins that new note.

Finger release does not produce another pair.

H. Paths not individually observable without changing gestures

Only ordinary-sound and ambient double taps cannot safely expose two separate physical touch-down events with the current exclusive SwiftUI TapGesture structure.

They are logged once when the existing double-tap callback completes. No gesture architecture was changed.
